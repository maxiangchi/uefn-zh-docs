Verse 程序化建筑模板

Verse - Procedural Building 模板用纯 Verse 实现了一套程序化建筑系统。本页介绍体素编辑、形状文法与波函数坍缩等玩法的实现原理。

英文原标题：Procedural Building Template In Unreal Editor For Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

Verse - Procedural Building 模板是 Unreal Editor for Fortnite（UEFN）（Fortnite 虚幻编辑器）的示例项目，出自Re: Imagine London(岛屿代码（Island Code）：1442-4257-4418)，展示了用 Verse 编写的程序化建筑（Procedural Building）系统。

程序化建筑系统完全用 Verse 实现、创建，而非在 Fortnite 中搭建。有了这套系统，你可以更精细地控制项目中网格体的拼装方式。

在 Fortnite 中，你可以用预置建筑构件（地板、天花板、墙体）设计玩法。程序化建筑系统扩展了你的可能性：你可以创建带分类的体素（voxel），分类决定了底层系统，系统放置网格体的同时，你可以快速放置更多体素。

要在 UEFN 项目浏览器（Project Browser）中打开该模板，请前往功能示例（Feature Examples） > 游戏示例（Game Examples） > Verse - Procedural Building。

程序化建筑系统分两个阶段工作：

  • 第一阶段，你编辑体素（voxel）网格——一个三维网格，每个单元格是一个盒子——通过添加或移除体素来编辑。
  • 第二阶段在体素网格每次被修改后运行。修改体素网格后，系统会取得体素信息并执行一套流程，在正确的位置生成正确的网格体。

你可以添加、移除 Building 与 Park 体素分类。每个分类有不同的规则，决定网格体如何生成。这些规则指的是从放置的体素到实际网格体之间要执行的操作图（或操作树）。

使用模板

项目中的每个关卡都有一个顶层类，即 root_device 类。玩家加入游戏时，root_device 类会为其创建 global_player_data，设置其 UI 信息。

每个建筑区都有一个 build_zone 设备，以体素单位定义场地尺寸。该设备的位置定义场地的原点。建筑区使用 build_system 对象处理建筑机制，用 spawner_device 生成建筑道具网格体。建筑区还持有 voxel_grid、mesh_grid 与 wfc_system。

每个建筑区包含以下内容：

  • build_zone（设备）——以体素单位定义场地尺寸。
  • build_system——处理建筑机制。
  • spawner_device（设备）——生成建筑道具网格体。
  • spawner_asset_references（设备）——引用所有生成的道具。

当玩家进入 build_zone（由Volume设备触发）时，会创建 player_data 来处理该玩家的输入与体素编辑。

使用体素构建

该模板引入 vector3i [type]()，用 X、Y、Z [integer]() 坐标表示体素。

下面是使用 vector3i 的示例脚本：

vector3i<public> := struct<computes><concrete>: @editable X<public>:int = 0 @editable Y<public>:int = 0 @editable Z<public>:int = 0

体素网格

体素网格是每个建筑区的三维单元格网格，存储每种建筑体素的类型信息。它在 voxel_grid 类中实现为一维数组，元素是对 voxel_cell [objects]() 的可选引用，如下所示：

# Main array representing the 3D grid of voxels var Cells<public> : []?voxel_cell = array{}

默认情况下，体素单元格对象只包含体素类型的 [enum]()，如下所示：

# Category of voxel in our build grid build_category<public> := enum: Building Park NewBuildingType # Structure stored for each occupied voxel voxel_cell<public> := struct<computes>: Category<public>:build_category

你可以按上面所示扩展该枚举，添加更多建筑体素分类。

下面的代码把三维体素坐标转换为一维[index]()：

# Gets the 1D array index from a 3D location in grid GetVoxelIndex<public>(X:int, Y:int, Z:int)<transacts>:int= return (X * (Size.Y*Size.Z)) + (Y * Size.Z) + Z

SetVoxel 与 ClearVoxel 是修改体素网格的关键函数。

射线检测

体素网格设置好后，系统执行射线碰撞检查，检查射线命中的体素面，即体素被射线命中的一侧。每个体素有六个面，类似骰子。做射线检测时，既要知道命中了哪个体素，也要知道命中了哪个面，才能绘制高亮并沿该面生成新体素。

射线碰撞检查主要在 ray_caster 类中处理。首先把摄像机位置变换到网格的局部空间，确定射线起始于哪个体素，再除以体素尺寸，如下所示：

CurrentVoxel := vector3i: X := Floor[InitialPosition.X / GridSize.X] Y := Floor[InitialPosition.Y / GridSize.Y] Z := Floor[InitialPosition.Z / GridSize.Z]

[Next]() 函数会被反复调用，判断射线接下来会穿过哪个体素，每次都检查该体素是否被视为实心。

建筑系统输入

player_data 中的 SelectModeTick_Trace 函数逐帧运行，处理大部分体素编辑与光标更新逻辑。两个[Input Trigger]()设备用于感知开火（Fire）与瞄准（Aim）按钮何时按下，并设置 PlacePiece 与 DeletePiece 逻辑变量。

该函数需要额外逻辑，因为 Park 体素被视为仅表面（surface only）：它们不阻挡射线，只能存在于实心体素（地面或建筑）之上。当你添加希望设为仅表面的新分类时，可以更新 CategoryIsSurfaceOnly 函数。

按住开火（Fire）按钮还能涡轮建造（turbo building），在平面上快速放置多个体素。该函数还会用 CheckPlayerOverlapsVoxel 函数检查体素添加前玩家是否在体素内部。

生成道具

该示例项目依赖在[runtime]()生成道具。creative_prop_asset 目前不会自动反映在 Verse 清单文件中，因此你需要用代理对象（piece_type_dir 类中 piece_type 的实例）来引用 Verse 中的特定道具。

spawner_asset_references 设备再为每个道具使用一个 @editable 字段，以及从代理到实际资产的映射表。要添加新网格体，必须先为其创建 BuildingProp，添加新代理，给设备添加新属性，再更新映射表（如下所示），最后重新编译并更新设备上的新属性，使其指向新道具：

Building1_corner:piece_type := piece_type{}
@editable BP_Building1_corner : creative_prop_asset = DefaultCreativePropAsset
PT.Building1_corner => BP_Building1_corner

Verse 中的程序化生成

该示例在 Verse 中实现了两种程序化生成：形状文法（Shape Grammar）与波函数坍缩（Wave Function Collapse）。形状文法应用于三维建筑，波函数坍缩用于二维（平面）区域。

两种技术都要求你先创建一套模块化建筑类道具，再由 Verse 在运行时生成。这段代码是确定性的，只按需删除、生成道具。

形状文法

为应用形状文法（Shape Grammar），某分类的所有体素会被转换为更大的凸包盒（convex box）。

形状文法由简单规则组成，每条规则接受一个盒子，为后续规则生成一个或多个子盒。

例如，一条规则可能把高盒切出一块一层体素高的楼板，把边角与墙体分配给不同规则。特殊规则可以在与盒子相同大小、相同位置生成道具。

每条规则定义为独立的 Verse 类，派生自 vo_base（体操作，volume operator）类。这些规则在派生自 rs_base（规则集，rule set）的类内部组装成规则集树。

这种方式简化了新规则的创建，便于尝试不同想法，能为每种建筑类型指定不同风格。同一组体素应用不同规则会得到不同结果。

下面是 vo_sizecheck 体操作的简单示例：

# Check all dimensions of a box are >= a certain size vo_sizecheck := class(vo_base): Size:vector3i = vector3i{X:=0, Y:=0, Z:=0} VO_Pass:vo_base = vo_base{} VO_Fail:vo_base = vo_base{} Operate<override>(Box:voxel_box, Rot:prop_yaw, BuildSystem:build_system):void= if(Box.Size.X >= Size.X and Box.Size.Y >= Size.Y and Box.Size.Z >= Size.Z): VO_Pass.Operate(Box, Rot, BuildSystem) else: VO_Fail.Operate(Box, Rot, BuildSystem)

它重写基类中定义的 Operate 函数，检查输入盒子的尺寸，决定调用接下来的哪条规则（vo_pass 或 vo_fail）。

在 Verse 中很容易搭建包含多个体操作（volume operator）的规则集。你可以重写 setupRules 函数，声明你的[operator]()与[parameter]()，起点（根操作）赋给 VO_root，如下所示：

# Rules for 'Building1' style rs_building1<public> := class(rs_base): RuleSetName<override>:string = "Building1" SetupRules<override>(PT:piece_type_dir):void= [...] # Rules for one floor of the building FloorRules := vo_cornerwallsplit: VO_CornerLength1 := vo_corner: VO_Corner := vo_prop: Prop := PT.Building1_corner

这种方式便于为不同建筑分类创建新操作与规则集。规则集在 build_system 的 InitRuleSets 中分配，在 SelectRuleSet 中为特定分类选择规则集。

波函数坍缩

波函数坍缩（Wave Function Collapse，WFC）是一种基于拼合规则随机生成区域的技术，规则决定哪些块可以相邻。

在这套实现中，你可以使用一组贴片（tile），指定其中哪些可以相邻。每条边都标注标签，只有标签匹配的贴片才能相邻放置。

下面是 wfc_mode_factory 类中的边标签示例：

WaterEL:wfc_edge_label := wfc_edge_label: Name:="Water" Symmetric := true

下面是上例的网格体定义示例：

Park_Grass_Water_InCorn:wfc_mesh := wfc_mesh: Props := array: PT.Park_Grass_Water_Incorn Name := "Park_Grass_Water_Incorn" Edges := array: WaterEL WaterEL WaterToGrassEL GrassToWaterEL

你可以按顺时针方向指定标签，从 +Y 方向开始。

本例的底边是“水到草地（water-to-grass）”，因为每条边都按顺时针考虑。有了这套系统，为玩法添加新标签、网格体或新 WFC 模型都很方便。

WFC 算法在网格上选一个位置，从可能选项中随机选择（坍缩）一个，再把这次选择的影响传播到其他位置的可能选项。这一过程持续到整个区域生成完毕。

wfc_system 类持有所有贴片的当前状态。特殊体操作 vo_wfc 读取状态并生成正确的网格体。

潜在扩展

下面是把该示例项目改造成新体验的几种方式：

添加新体素分类 / 形状文法

  • 扩展 build_category 枚举
  • 更新需要处理新分类的 case 语句
  • 创建派生自 rs_base 的新规则集
  • 更新 SelectRuleSet，为新分类使用新规则集

为公园 WFC 模型添加新网格体

  • 为每个新网格体创建建筑道具（Building Prop）（如上文生成道具所述）。
  • 在 wfc_model_factory 的 GetParkModel 中添加新的 wfc_edge_label（如有需要）。
  • 为每个新网格体 / 道具添加新的 wfc_mesh 实例，定义每条边的标签。
  • 为每个新网格体调用 Model.AddMesh。

添加新 WFC 模型

  • 为新模型添加新体素分类。
  • 在 wfc_model_factory 中添加新函数创建新模型。
  • 在 build_system 中添加新的 wfc_model 成员（如 Park_WFCModel）。
  • 添加类似 AddParkWFCTile 的新函数，用新模型添加贴片。
  • 修改 SelectModeTick_Trace，为新分类调用新函数。

你还可以程序化地生成体素。示例项目中有按钮，可在建造区添加随机建筑或公园区域。它使用 build_system 的 ClearRegion 与 AddRegion 函数，可作为随机生成关卡系统的起点。

Verse 性能

该示例项目的 Verse 代码确保代码足够快，能实时处理更新。由于处理大数组可能导致性能问题，请牢记以下信息：

  • 用 for 循环返回数组比逐个元素构建更快，因为每次追加都会复制数组，复杂度可能达到 O(N2)。例如： 
    * set OptionalArray := for(I := 0 .. ArraySize-1): false
  • 不要按值传递大数组，而是把它们放进对象，调用方法或传递对象。
  • 多维数组很慢，因为第一个 [] 操作符会把拷贝传给下一个 [] 操作符。
  • 对数组调用 .Length 实际会在那一刻复制数组，所以自行跟踪大数组的大小可能更快。

使用 profile 宏也很有帮助，可以准确了解代码的哪些部分最耗时。
