42.00 生态系统更新与发行说明

v42.00 生态更新：Unreal MCP 接入 UEFN、触屏手势转正、实验性能力系统、Telekineticon 物理道具与问题修复汇总。

英文原标题：42.00 Fortnite Ecosystem Updates and Release Notes · 查看英文原文 · 社区翻译镜像，仅供学习

v42.00 生态系统更新将 Unreal MCP 带入 UEFN（Unreal Editor for Fortnite），你可以把 Claude Code、Codex 或 Cursor 等智能体编码工具直连到编辑器。经由虚拟指针（Virtual Pointer）的触屏输入手势已结束实验状态——点击（tap）与拖拽（drag）已可用于正式游戏，全新的实验性能力系统（Ability System）则为 Verse 可复用玩法能力提供了框架。快来看看 Telekineticon 物理道具（实验性）与 Heatwave Harbor 预制件和画廊吧！

Unreal MCP 现已登陆 UEFN

随 UE 5.8 一同发布的 模型上下文协议（Model Context Protocol，MCP）插件 Unreal MCP，现已登陆虚幻编辑器 Fortnite 版（UEFN）。

UEFN 在编辑器内部嵌入了 MCP 服务器（MCP server），因此 Claude Code、Codex 或 Cursor 等智能体编码工具可以与你协同工作，降低技术门槛，帮你更快搭建、更快迭代。这包括编写与编译 Verse、放置与配置设备、创建 Scene Graph 实体、用 UMG 搭建 UI，以及运行试玩会话来测试成果等能力。智能体产出的每一样东西都是项目中真实、可编辑的一部分：可以打开的 Verse 文件、可以在细节面板中调整的设备、可以在大纲视图中选中的实体。MCP 是开放标准，任何支持它的智能体编码工具都可以在本地连接，协助你在 UEFN 中开发体验。

本次发布的 Unreal MCP 附带专为 UEFN 打造的工具集（toolsets），通过同一套 Toolset Registry 分发——在通往 UE6 的路上，随着我们统一开发管线，UEFN 功能也将由该机制驱动。

详情请参阅官方博客。完整设置与配置请参阅 UEFN MCP 文档。

移动端控制：触屏输入手势（经由虚拟指针）结束实验状态

虚拟指针（Virtual Pointer）让玩家能以兼容所有受支持输入设备的方式与屏幕元素交互，现已可集成到正式游戏中。这为移动设备解锁了更多触屏控制，包括点击（tap）与拖拽（drag）。反投影 API（De-projection API）也已结束实验状态，开发者可以知道玩家在世界空间中触碰的是什么。

捏合（pinch）操作（用于镜头缩放与对象缩放等功能）目前仍处于实验阶段。

更多信息请参阅 Virtual Pointer 文档。

更多工具，助力你的岛屿移动端体验

用 41.00 中发布的其他移动端工具，进一步提升岛屿的移动端体验：

  • 开发者可自定义触屏控制（Developer Customizable Touchscreen Controls）：把触屏布局构建为 UMG 用户挂件（UMG User Widget），为每个动作（跳跃、射击、换弹、瞄准、下蹲、疾跑等）使用触屏控制布局覆盖（Touch Control Layout Override）挂件，再将其指派给 HUD 控制器（HUD Controller）设备，即可重排、换肤或隐藏单个按钮。
  • 可点击自定义 HUD 挂件（Tappable Custom HUD Widgets）：自定义 HUD 挂件如今可充当触屏按钮。用宝石计数器、奖励通知、背包图标等 HUD 元素驱动逻辑，还可以把体验中用不上的默认动作挪作他用。
  • 平台控制查询（Platform Controls Query）：全新的 Verse API 可检测玩家是否在使用支持触屏的设备，以及该平台相关的控制方案，从而把玩家引导到适合其设备的体验。

另请查看 为移动端设计（Designing for Mobile）指南，其中包含在 Fortnite 与 UEFN 中设计移动端游戏的原则与最佳实践。

移动端性能优化：资产健康工具改进

在频繁崩溃的岛屿上，不少内存不足（out-of-memory）问题来自不符合内存规范的资产——这在移动端影响尤为显著。42.00 的资产检查覆盖面更广，包括缺失 LOD 与 Min LOD for Quality 设置不正确等问题，风险会在搭建过程中以资产警告的形式浮现，而不是等玩家踩坑后才暴露。没有 LOD，低配设备就只能加载全精度几何体；而 Min LOD for Quality 正是让它们降到低细节 LOD 的开关。网格导入现在默认采用对移动端友好的设置，资产离“可发布”更近了一步。检查还会标出问题并指向可选的一键修复。

性能分析工具改进

我们正在把 Timing Insights 引入 UEFN，它能像 UE 开发者所依赖的那样，拆解你的岛屿每一帧的时间开销。适合正在追查卡顿（hitching）或低帧率、此前只能靠逐个关闭系统来定位元凶的开发者——现在可以直接找到最耗时的部分。Timing Insights 度量的是帧时间而非内存，分析的是实时会话。

能力系统（Ability System，实验性）

全新的实验性代码原生能力系统（code-native Ability System）现已可用。能力系统（Ability System）是用 Verse 创建可扩展、可复用玩法能力的框架，可用来创建赋予玩家魔法技能、超级能力或其他特殊能力的玩法。

你可以通过两种方式创建能力——结构化模板，或用 Verse API 做更深度的自定义。

注：本节为早期实验性（Experimental）版本，API 仍可能随开发推进而变化。我们正在朝结束实验状态努力，现在就可以开始搭建，以便正式发布时做好准备！

更多信息请参阅 能力系统 Ability System 文档。

Fortnite 模板能力（Fortnite Template Abilities，实验性）

Fortnite 模板能力（Fortnite Template Abilities）为你提供了实用的能力搭建与自定义方式：在时间轴的特定时刻放置动画、音频与玩法效果。它为创建与迭代玩法动作提供了结构化框架，支持可配置的激活、目标选择、时序与执行。

更多信息请参阅 Fortnite Template Abilities 文档。

Verse 能力 API（Verse Abilities API，实验性）

完全用 Verse 定义、激活与管理玩法能力，全面掌控激活条件、目标选择与生命周期。这是需要超越模板能力的自定义逻辑时的正确起点。

更多信息请参阅 Verse Abilities API 参考。

Verse 镜头修正器（Verse Camera Modifiers，实验性）

我们开放了一组通用镜头修正器（Camera Modifiers），与实验性镜头 API（Camera API）相辅相成。这些修正器上的属性与开发者今天可用的设备类似，但可在 Verse 中于运行时管理。每个镜头修正器都经过精心调校，响应灵敏且高度参数化，支持高质量、精雕细琢的玩法：

  • 环绕镜头修正器（Orbit Camera Modifier）：跟随并环绕目标实体的第三人称摇臂镜头。适用于第三人称角色镜头，或镜头需跟随目标并保持可调距离与高度的其他配置。
  • 固定角度镜头修正器（Fixed Angle Camera Modifier）：以恒定视角跟随目标，适用于等距、俯视、侧视及类似固定视角配置。
  • 固定点镜头修正器（Fixed Point Camera Modifier）：静止镜头，原地旋转以保持一个或多个目标实体在画面中，适用于监控镜头、观战视角、演出桥段等位于固定世界位置的镜头。

镜头 API 与这些修正器仍处于实验阶段，该功能正在积极开发中。

全新念力工具 Telekineticon，物理操控工具（实验性）

注意：Telekineticon 在 v42.00 中以实验性（Experimental）发布，使用它的岛屿暂不可发布。

我们新增了一个物理（Physics）物品 Telekineticon，开发者可用它构建玩家可拾取、放下与移动物理 creative_props 的游戏。使用前需要启用 Physics 与物品化（Itemization）。

基于 Verse 与全新物品化架构，Telekineticon 是可在编辑时配置的物品，你可以基于它的函数与事件构建玩法。

更多信息请查看 Telekineticon 文档页。

社区帖子支持嵌入 YouTube 视频

在 Fortnite Communities 的帖子正文中嵌入 YouTube 视频。视频仅在 Web 端完整帖子（communities.epicgames.com）中显示，不在客户端内显示。

在 Fortnite Communities 的帖子编辑器中点击 Video 按钮即可添加 YouTube 视频。玩家无需离开帖子即可点击观看嵌入的 YouTube 播放器。

玩家可以直接在 Fortnite Communities 的帖子中点击内嵌的 YouTube 播放器播放视频。

  • 修复了 FortWaterBodyExclusionVolume 未考虑排除模式、导致玩法不支持默认 Remove Water Bodies List From Exclusion 的问题；修复了加载未升级可见层的地形流送代理 actor 时的误报 map check；修复了删除地形组件时的潜在死循环；修复了 Smooth/Flatten 工具导致的非法地形纹理；修复了组件删除后 Nanite 地形未更新；修复了绘制模式下 Smooth/Flatten/Noise 丢失目标层；修复了 Flatten 工具在部分地形渲染器上的目标类型支持；UEFN Show 视口菜单暴露 Advanced > Bounds 以查看建筑周围草地排除区；修复了 UEFN 中水体与地形碰撞显示。

新增：

  • 大纲视图覆盖图标（override icon）现仅反映用户有意义的覆盖，实体图标聚合其后代（任一子级有真实覆盖即点亮）；重算使用 FOverridableManager::GetOverriddenState，抑制放置噪声；同步观察者与翻转门控处理器通过 FEntityOverrideAggregateDirtyTag 弄脏祖先行并重聚合；悬停图标现列出覆盖项，与图标及细节面板一致。
  • 更新 SubobjectEditor 提示以显示预制件来源并移除无关的 Mobility 与 Editor Only 信息；预制件编辑器新增最大化/还原视口选项；底部新增计数挂件 X items: Y prefabs, Z entities (I selected)；修复预制件编辑器 Tag 的 Show Tag Hierarchy 选择跨会话不持久；修复客户端收到 OnRep_LocalTransformInternal() 且设置原点时未调用 UpdateTransform()；恢复缺失的世界右键菜单（含 Save Entities as External/Internal Files，可选择加入/退出 OFPE）。

Verse 更新与修复

新增：

  • VE 2.0 支持未烘焙编辑器；基于 CVar verse.ShowBuiltInSource 显示源码 .verse 文件（未烘焙 UEFN 与 VersePrototypes 默认开启）。
  • 弃用 FTextInspector::GetSourceString（返回 const FString* 实则永不为空），改用返回 const FString& 的 GetSourceStringRef 并更新调用。
  • VerseLocalizationHelper 本地化失败时返回未本地化字符串，便于诊断而非显示空串。
  • TwinSiphonShotguns_BR_CH7S2_Exotic 现已可在 Verse 中使用。

修复：

  • 将刷屏警告 GetOrCreateAgentFromController: Can't get a verse::player before their unique net id is valid 降为 Verbose 日志，缓解启动日志刷屏。
  • 修复了此前合法、如今非法的 Verse 语法导致的编译错误：scoped 限定的接口中 internal 成员不再对 scoped 目标模块可见，需将 internal 访问器改为 public 或 protected。详见 Scoped specifiers。

不再允许：

A := module:
    base<scoped{B}> := interface:
        Func():void = {}
B := module:
    using{A}
    some_class := class(base):
        Func<override>():void = {}

或

A := module:
    base<scoped{B}> := interface:
        Func<internal>():void = {}
B := module:
    using{A}
    some_class := class(base):
        Func<override>():void = {}

允许：

A := module:
    base<scoped{B}> := interface:
        Func<public>():void = {}
B := module:
    using{A}
    some_class := class(base):
        Func<override>():void = {}

语言（Language）

新增：

  • 弃用 fort_vehicle 中的 GetPassengers()，请改用 GetOccupants()。
  • 移除跨模块 concrete/abstract 限制：concrete 类型现可继承另一模块的 abstract 基类型。典型场景是标签（tags）：基类型 tag 为 abstract，此前无法以其为基定义 concrete 子类型，现在可以这样写：
my_tag := class<concrete>(tag):

并在字段中使用：

@editable selected_tag_type:castable_concrete_subtype(tag) = my_tag

修复：

  • 当名称解析到版本门控定义时，改进了未知标识符错误提示。

工具（Tools）

新增：

  • @deprecated/@discontinued/@experimental 的传播来源现显示警告文本：当标记来自外层容器（module、class、struct、interface 或 enum）而非叶子引用本身时，分析器会在警告文本后追加“（via enclosing <kind> '<source>'）”，让作者直观看到真正的标记来源。

示例：之前：

'(/Verse.org/A/MyClass:)Foo' is deprecated: Use NewClass.

之后（Foo 未直接标记，@deprecated 在 MyClass 上）：

'(/Verse.org/A/MyClass:)Foo' (via enclosing class '(/Verse.org/A:)MyClass') is deprecated: Use NewClass.

修复：

  • 修复了 UEFN 中默认 creative_prop_asset @editable 的 Browse-to 不工作的问题。
