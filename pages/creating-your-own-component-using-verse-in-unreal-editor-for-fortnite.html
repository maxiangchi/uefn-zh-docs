使用 Verse 在 UEFN 中创建自己的组件

学习使用 Verse 为实体编写自定义组件，实现生成与移除实体、增删组件，以及循环消失等自定义行为。

英文原标题：Creating Your Own Component Using Verse in Unreal Editor for Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

注：本页介绍的是 Beta 功能，欢迎学习使用，但在正式发货的项目中使用时请谨慎。

你可以使用 Verse 创建自己的组件，并将其添加到实体上。借助自定义的 Verse 组件，你可以从场景中生成和移除实体、为实体添加或移除组件，还可以创建自己的行为（例如让实体循环消失），或者实现任何你能想到的玩法！

创建新的 Verse 组件

你可以从 Verse 模板文件创建新的 Verse 组件。

创建新的 Verse 组件：

  1. 在实体的 Details（详情）面板中，选择 Add Component > New Verse Component（添加组件 > 新建 Verse 组件）。
  1. 你也可以通过 Verse Explorer（Verse 资源管理器）添加新的 Verse 文件，来创建新的 Verse 组件。
  2. 在 Verse 代码模板列表中，选择 Scene Graph Component（场景图（Scene Graph）组件）。
  3. 将 Component Name（组件名称）设置为你的 Verse 组件的名称。在本示例中，该组件命名为 my_verse_component。
  4. 点击 Create（创建）以创建 Verse 组件文件。之后，当你为实体选择添加组件时，你编写的 Verse 组件就会出现在组件列表中。

同一个组件类或其子类只能添加一个。例如，一个实体上只能有一个 mesh_component（网格体组件）。这一限制会延伸到组件的子类：如果你已经为实体添加了 capsule_light_component（胶囊体光源组件），就不能再添加 rect_light_component（矩形光源组件），因为两者都是 light_component（光源组件）的子类。同样的限制也适用于你在 Verse 中制作的自定义组件。

组件生命周期

组件在被添加到实体、加入场景并开始在模拟中运行的过程中，会经历一系列生命周期函数。你的 Verse 组件应当重写这些方法，以便完成初始化设置并运行模拟。

当组件关闭时，它会经历与之对应的关闭版本函数，让你有机会在组件被销毁之前清理组件上保留的所有状态。

以下是组件的生命周期状态：

  • Initialized（已初始化）
  • AddedToScene（已加入场景）
  • BeginSimulation（开始模拟）
  • EndSimulation（结束模拟）
  • RemovingFromScene（正在移出场景）
  • Uninitializing（正在取消初始化）

组件生命周期函数与设备生命周期不同。组件逻辑在编辑模式和游玩模式下都会运行，你添加的任何行为都会在启动会话后立即运行。如果你希望组件逻辑只在游戏开始时运行，可以在 Verse 设备的 OnBegin() 函数中生成预制件。

使用 Verse 查询实体与组件

在 Verse 代码中有多种查找实体和组件的方法。你组织实体和组件的方式，会影响你在 Verse 代码中查询和开发功能的方式。

在 Verse 中查询实体和组件时，需要从一个实体出发，返回它在层级结构中上方或下方嵌套的实体。你可以查询某个实体的直接父级或子级，也可以查询它的全部祖先实体和后代实体。

按组件类型获取实体

你可以对想要查询的实体发起调用，查找所有带有特定类型组件的实体。如果被查询的实体是模拟实体（simulation entity），则会返回场景中所有带有该类型组件的实体。

在下面的示例中，Verse 组件会获取所有附加了 light_component 组件的实体。对于找到的每个实体，它都会生成一个 particle_system_component（粒子系统组件）并附加到这些实体上。其中，BlowingParticles 是一个在 Assets.digest.Verse 文件中引用的 Niagara（尼加拉）发射器。

light_component 是你可以添加到实体的所有不同光源组件类型的超类。在下面的查询中，LightComponent 用于查找带有任意种类光源组件的实体。

# Runs when the component should start simulating in a running game.
OnBeginSimulation<override>():void =
    # Run OnBeginSimulation from the parent class before
    # running this component's OnBeginSimulation logic
    (super:)OnBeginSimulation()
    for:
        LightComponent : Entity.GetSimulationEntity[].FindDescendantEntitiesWithComponent(light_component) do:
            # Create a particle system component and add it to the entity.

下一个示例展示了如何使用 FindDescendantEntitiesWithComponent() 函数，查询 Verse 组件所附加实体之下嵌套的所有带粒子系统的实体。同理，你也可以使用 FindAncestorEntitiesWithComponent() 获取带有特定组件的全部祖先实体。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically canceled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void=
    # Get all entities that have particle system components nested under the entity this component is attached to.
    ParticleSystemEntities := Entity.FindDescendantEntitiesWithComponent(particle_system_component)
    # Get all entities with particle system components that are ancestors of this entity.

如果你需要在整个场景中查询实体，可以先获取模拟实体，再基于它执行查询。这样会从实体结构的最顶层开始，查找所有符合查询条件的嵌套实体。要访问模拟实体，可以对 Verse 组件所附加的实体调用可失败函数 GetSimulationEntity[]。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically canceled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void=
    # Get the simulation entity.
    if:
        SimulationEntity := Entity.GetSimulationEntity[]
    then:

让 Verse 组件频繁地在实体树中向上、向下查找可能开销较大。如果你的行为依赖于特定的实体结构，那么实体结构的任何细微变化都可能导致行为发生非预期的改变，甚至完全失效。

另一方面，这也意味着你的组件需要的前置设置更少：你只需要添加 Verse 组件并保证实体结构正确即可。在创建实体和开发 Verse 组件逻辑时，请时刻权衡这两方面的利弊。

请查阅 SceneGraph 模块，了解在 Verse 中操作实体和组件的全部方式。下面介绍代码中查询实体和组件的一些常用方法。

获取实体的组件

你可以调用 GetComponent[]，用 Verse 获取实体上特定类型的组件。这对于创建依赖其他组件行为的自定义逻辑非常有用。例如，根据灯光颜色使用 sound_component（声音组件）播放音频，或根据实体是否位于特定区域来获取 particle_system_component（粒子系统组件）并施加效果。

在下面的示例中，Verse 组件让平台循环反复出现和消失。它通过获取实体上的网格体组件并将其禁用，经过设定的时长后再重新启用来实现。

using { /Verse.org }
using { /Verse.org/Native }
using { /Verse.org/Simulation }
using { /UnrealEngine.com/Temporary/SceneGraph }
# A Verse-authored component that can be added to entities.
# This component will make the entity appear and disappear on loop.
disappear_on_loop_component := class<final_super>(component):
    # How long in seconds the entity should be hidden.
    @editable

在另一个示例中，Verse 组件获取实体上的 light_component 并将其颜色改为深橙色。light_component 是你可以添加到实体的各种光源的超类，因此这个示例可以找到它的任意子类组件。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically canceled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void=
    # Find any component on this entity that subclasses from light_component.
    if:
        LightComponent := Entity.GetComponent[light_component]
    then:

获取全部组件

你可以使用 GetComponents() 函数返回实体上的全部组件。由于代码事先不知道这些组件的具体类型，你可以使用类型转换，根据每个组件的类型执行不同操作。下面的示例获取实体上的全部组件数组，并尝试将它们转换为 enableable 类型。如果转换成功，说明该组件实现了 enableable 接口，随后会禁用每一个实现该接口的组件。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically canceled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void=
    # Get a list of all components on the entity.
    ComponentList := Entity.GetComponents()
    for:
        Component:ComponentList

按 Verse 标签查找实体

你可以为实体添加标签组件，从而在场景中找到特定实体，这类似于为 Actor 添加 Verse 标签。当你不想依赖容易变化的因素（例如实体拥有哪些组件或位于场景中的什么位置）来挑选要操作的实体时，这种方式非常有用。

这是因为，依赖容易变化的因素会在你修改项目、新增实体时给游戏带来非预期的行为。你可以在编辑器中为实体添加 tag_component（标签组件），并从 Tags（标签）下拉框中选择标签，也可以在 Verse 代码中使用 AddTag() 函数添加标签。

下面的示例从模拟实体出发，查询其后代中在 tag_component 上标记了 my_tag 标签的全部实体。

# will be automatically cancelled when the component is disposed or the
# game ends.

用重叠查找实体

碰撞体是表示网格体碰撞形状的体积（volume）。你可以用它们查询特定形状内重叠的物体，例如当物体过于靠近塔楼时造成伤害，或检测足球何时进入球门。在 Verse 中，你可以使用 FindOverlapHits() 函数查找特定区域内的全部实体。

这个区域可以是实体自身、给定的碰撞体（例如球体或盒体），也可以是用于模拟实体位置的一个位置点。该函数会返回 overlap_hit 列表。每个 overlap_hit 都会提供与源体积重叠的组件或体积的信息，你可以查询这些组件以找到它们关联的实体。

下面的示例以实体的变换为中心创建一个半径为 256.0 单位的球体，然后查找该球体内的全部重叠，返回 overlap_hit 列表。由于每个 overlap_hit 不是组件就是体积，你可以查询 TargetComponent 或 TargetVolume 来判断它的类型。如果 overlap_hit 是组件，代码会进一步获取该组件的实体，最后检查该实体是否有光源组件，如果有，就把灯光颜色变为蓝色。只要体积足够大，仅用几行代码就能改变岛屿上每一盏灯的颜色！

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically canceled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void=
    # Define a volume to find entities within.
    # This is a sphere whose radius is 256.
    CollisionSphere:collision_sphere = collision_sphere:
        Radius := 256.0

这段代码模拟了一个以立方体实体为中心、半径为 256.0 单位的重叠 collision_sphere（碰撞球体）体积（图中圆形所示），返回该球体重叠到的全部组件或体积；然后获取每个被重叠组件的父实体，并将其中的光源组件变为蓝色。由于立方体在重叠开始时位于 collision_sphere 内部，它会被包含在 overlap_hit 列表中并同样变蓝。请注意，最右侧的红色锥体实体在 collision_sphere 之外，因此不会重叠，也不会变蓝。

用扫描查找实体

另一种重要的实体查询方式是扫描（sweep）。扫描是指让物体沿特定向量移动一段距离，例如让方块横穿平台把玩家推下缝隙，或向前方直线发射导弹摧毁墙体。

在 Verse 中，你可以使用 FindSweepHits() 函数模拟扫描，以查询物体之间的碰撞。该函数接收一个位移向量，用于模拟物体沿该向量扫描的过程。你可以用父实体或给定的碰撞体执行扫描，并指定开始扫描的全局变换。

FindSweepHits() 函数返回 sweep_hit 列表。每个 sweep_hit 提供与 overlap_hit 相同的信息，例如命中（hit）的组件或体积、执行扫描的源体积或组件，此外还提供接触位置、法线、面法线，以及命中发生在扫描路径上多远处等信息。

下面的示例获取一个实体并调用 FindSweepHit()，传入一个 Forward（前向）分量长度为 1000.0 的向量。代码模拟该实体沿前向正方向移动 1000.0 单位时会发生哪些碰撞，并返回 sweep_hit 列表。

由于每个 sweep_hit 不是组件就是体积，你可以查询 TargetComponent 或 TargetVolume 来判断它的类型。如果命中是组件，代码会获取该组件的父实体，最后检查该实体是否有光源组件，如果有，就把灯光颜色变为蓝色。

for:
    # Simulate sweeping this entity 1000 units in the positive X direction, and return any components and volumes it overlaps with.
    SweepHit : Entity.FindSweepHits(vector3{Left := 0.0, Up := 0.0, Forward := 1000.0}, Entity.GetGlobalTransform(), CollisionBox)
    # Check that the overlap is a component, and if so get its parent entity.
    # Then if the entity has a light component, change its color filter.
    TargetComponent := SweepHit.TargetComponent
    TargetEntity := TargetComponent.Entity
    LightComponent := TargetEntity.GetComponent[light_component]
do:

这段代码模拟将立方体实体沿 X 正方向扫描 1000.0 单位，返回它重叠到的全部组件；然后获取被重叠组件的父实体，并将其中的光源组件变为蓝色。请注意，命中列表不包含执行扫描的实体自身，因此立方体自身不会变蓝；最右侧的红色锥体实体在扫描范围之外，也不会变蓝。

接下来的示例与上一个类似，区别在于它先构造了一个 collision_box（碰撞盒）体积，再以立方体实体中心为起点，沿前向正方向扫描 1000.0 单位。由于立方体在扫描开始时位于 collision_box 内部，它会被包含在 sweep_hit 列表中并同样变蓝。

# Define a volume to sweep over entities.
# This box is 1/4th the size of a standard 512x512 grid tile.
CollisionBox:collision_box = collision_box:
    Extents := vector3:
        Left := 128.0,
        Up := 128.0,
        Forward := 128.0
for:
    # Simulate sweeping the CollisionBox 1000 units in the positive X direction, and return any components and volumes it overlaps with.
    SweepHit : Entity.FindSweepHits(vector3{Left := 0.0, Up := 0.0, Forward := 1000.0}, Entity.GetGlobalTransform(), CollisionBox)

这段代码模拟将 collision_box（碰撞盒）体积（图中黄色方框所示）沿前向正方向扫描 1000.0 单位，返回它重叠到的全部组件；然后获取被重叠组件的父实体，并将其中的光源组件变为蓝色。由于立方体在扫描开始时位于 collision_box 内部，它会被包含在 sweep_hit 列表中并变蓝；最右侧的红色锥体实体在扫描范围之外，不会变蓝。

使用 Verse 生成与移除实体

你可以对实体调用 RemoveFromParent() 将其从场景中移除；对将成为父实体的实体调用 AddEntities()，即可把新的或之前移除的实体添加到场景中。

在下面的示例中，Verse 组件查找所有标记了玩法标签（Gameplay Tag）my_tag 的实体，将每个找到的实体从其父级移除（即把实体从场景中移除），五秒后再把同一实体加回其父级，从而让它在场景中重新生成。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically cancelled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void =
    # Find all entities tagged and get their parent entity.
    for:
        TaggedEntity : Entity.GetSimulationEntity[].FindDescendantEntitiesWithTag(my_tag{})
        Parent := TaggedEntity.GetParent[]

同理，你可以调用 AddComponents() 并传入要添加的组件列表，为实体添加组件；对实体调用 RemoveFromParent() 可以移除实体，对组件调用 RemoveFromEntity() 可以从实体上移除组件。被移除的实体和组件可以分别用 AddEntities() 和 AddComponents() 重新加回场景。请注意，加回场景的已移除组件无法更改其父实体。

预制件

你在项目中创建的预制件（Prefab）会作为类暴露给 Verse，位于项目中的 Assets.digest.verse 文件里。预制件中定义的实体和组件，可以通过预制件上的 GetEntities() 和 GetComponents() 调用在 Verse 中访问。

你可以通过实例化预制件类并将其添加到场景中的实体上来生成预制件实例。在下面的示例中，Verse 组件创建了预制件的一个实例（该预制件在编辑器中名为 loop_disappearing_platform_prefab），并将其添加到场景中。

# Runs when the component should start simulating in a running game.
# Can be suspended throughout the lifetime of the component. Suspensions
# will be automatically cancelled when the component is disposed or the
# game ends.
OnSimulate<override>()<suspends>:void =
    if:
        SimulationEntity := Entity.GetSimulationEntity[]
    then:
        # Create an instance of the disappearing on loop platform from its prefab.
        DisappearingPlatform:disappearing_platform_prefab = disappearing_platform_prefab{}

最佳实践与技巧

在 Verse 中创建自己的组件时，请牢记以下最佳实践与技巧：

  • Verse 组件如果依赖其他组件，通常应与这些组件位于同一实体上。
  • 组件同时暴露物理前（pre-physics）与物理后（post-physics）每帧触发的 tick 事件。如果你需要在物理生效前执行某些逻辑（例如修改变换），或在物理生效后执行某些逻辑（例如读取物体经过物理结算后的位置），这些事件会很有用。
  • 如果你并没有特别需要物理前或物理后事件，建议继续使用 Verse 并发表达式，基于特定逻辑控制时间流。更多详情请查阅时间流与并发（Time Flow and Concurrency）。
  • 组件生命周期函数与设备生命周期不同。组件逻辑在编辑模式和游玩模式下都会运行。如果你希望组件逻辑只在游戏开始时运行，可以在 Verse 设备的 OnBegin() 函数中生成预制件。
