岛内交易设备模板

岛内交易（In-Island Transactions）Verse 设备内置了完整的交易模板，涵盖 Verse API 中 Marketplace 模块的关键实现，包括物品、报价、捆绑包报价，并利用默认店面 UI 处理购买。把它作为快速搭建店面的指南。

英文原标题：In-Island Transactions Device Template · 查看英文原文 · 社区翻译镜像，仅供学习

岛内交易（In-Island Transactions）Verse 设备包含岛内交易的模板代码。它实现了 Verse API 中 Marketplace 模块关键方面的全部实现，包括物品（items）、报价（offers）、捆绑包报价（bundle offers），以及利用默认店面 UI 处理购买的逻辑。请将这份代码作为快速搭建店面的指南。

访问该设备的方法：

  1. 导航到 Verse Explorer。
  2. 右键点击你的项目名称。
  3. 选择 Add new Verse file to project（向项目添加新的 Verse 文件）。
  4. 选择 In-Island Transactions Device（岛内交易设备）。

创建物品

物品在 Verse 中被定义为权益（entitlements），分为两类：消耗品（consumable items），使用后会从玩家物品栏中移除；耐用品（durable items），玩家可以反复使用而不会从物品栏中移除。

EntitlementInfo 模块

模块（Modules）是原子化的代码单元，可以被重新分发，供多个文件使用。模块可以随时间变化，而不会破坏已使用该模块的文件中的依赖关系。你可以将冗长或重复的代码单元（例如权益定义）分离到另一个文件中，然后用 using 语句导入它。

EntitlementInfo 模块汇总了模板中所有权益的名称、描述和简短描述。在任何需要定义权益的文件中引入该模块，就无需为同一商品反复重新定义名称和其他变量，这让权益信息的修改更简单，也降低了调试权益的复杂度。

# Setup your entitlements and offers data, in this case that's your Names, Descriptions & Short Descriptions as well as any other data you want to be constant
EntitlementInfo<public> := module:
    Potion<public> := module:
        Name<public><localizes>:message = "Potion"
        Description<public><localizes>:message = "Adds +10 health when used. Green so you know its healthy!"

定义权益

每个 Verse 权益都具有以下属性：

  • Name（名称）：权益名称，最多 50 个字符。
  • Description（描述）：随权益一起显示的长描述，最多 500 个字符。
  • ShortDescription（简短描述）：用最多 100 个字符概括权益的短描述。
  • Icon（图标）：权益的图片。

如果你的权益是付费随机物品（paid random item），必须在描述中包含玩家可能获得内容的准确数字概率。更多信息请参阅 Paid Random Items（付费随机物品）。

Verse 权益还可以具有以下可选属性：

  • MaxCount（最大数量）：玩家同一时间可拥有的该权益的最大数量。
  • Consumable（可消耗）：如果设为 true，该权益可以用 ConsumeEntitlement 消耗，每次消耗会减少用户在 Epic 系统中拥有的该权益总数。如果设为 false，该物品为永久物品，使用时不会被消耗。
  • PaidArea（付费区域）：如果设为 true，该权益提供进入付费墙后区域的权限。
  • PaidRandomItem（付费随机物品）：如果设为 true，这些权益通过购买或兑换内容来获得随机奖励。
  • ConsequentialToGameplay（影响玩法）：如果设为 true，该物品会在你的岛屿中提供有意义的优势。详情请参阅创建物品与报价中的 Consequential to Gameplay（影响玩法）一节。

在下面的代码片段中，你将使用前面定义的 EntitlementInfo 模块来构建权益定义。要定义消耗品权益，必须将 Consumable 设为 true。

在定义权益之前，需要创建一个基础权益类，供体验中的权益使用——在本例中为 feature_example_entitlement。

还需要为每个权益定义指定一个图标纹理的文件路径，否则权益定义将无法通过验证。

Entitlements<public> := module:
    using {EntitlementInfo}
    # The base entitlement you should define for ALL your entitlements in your experience
    feature_example_entitlement<public> := class<abstract><castable>(entitlement){}
    basic_sword<public> := class<concrete>(feature_example_entitlement):
        var Name<override>:message = Sword.Name

默认情况下，物品不是 Consumable（可消耗品），且 MaxCount 为 1。如果物品是 Paid Area（付费区域）、Paid Random Item（付费随机物品），或提供影响玩法的实质性优势，则必须在代码中定义相关字段。

权益报价

报价（offer）为物品或资产指定一个以 V-Bucks 计价的价格。每个报价都有自己的名称、描述和图标，与权益规格相互独立。报价在 Verse 中定义。

要出售权益，必须为该权益准备一个对应的报价。

每个报价都具有以下属性：

  • Name（名称）：报价名称。
  • Description（描述）：随报价一起显示的长描述。
  • ShortDescription（简短描述）：在较小对话框中概括报价的短描述。
  • Icon（图标）：报价的图片。
  • EntitlementType（权益类型）：声明报价中包含的权益。
  • Price（价格）：以 V-Bucks 计价的价格。不得低于 50 V-Bucks，不得高于 5000 V-Bucks，且必须以 50 为倍数设置。

以下代码片段演示了如何定义权益报价，这里复用了已有的 EntitlementInfo 模块来提供基础的权益报价信息。还需要定义图标、EntitlementType（定义报价对应的权益）以及以 V-Bucks 计价的价格。还可以根据固定值、国家代码来定义可选的最低购买年龄，或按平台系列限制报价访问权限，或组合使用这些条件，下面的代码片段演示了其中一些示例。

注：Subdivision codes（二级行政区代码）目前不受支持，将在未来版本中提供。
ExampleOffers<public> := module:
    using {EntitlementInfo}
    basic_sword<public> := class(entitlement_offer):
        var Name<override>:message = EntitlementInfo.Sword.Name
        var Description<override>:message = EntitlementInfo.Sword.Description
        var ShortDescription<override>:message = EntitlementInfo.Sword.ShortDescription

以 V-Bucks 计价的价格必须是 50 的倍数，且介于 50 至 5000 V-Bucks 之间。

对于付费随机物品，必须确保玩家能在报价详情中看到获得每种付费随机物品的准确数字概率。否则将被视为违反 Fortnite 开发者规则，你和你的岛屿将受到相应处罚。

更多信息请参阅 In-Island Transactions Restrictions（岛内交易限制）。

捆绑包报价

捆绑包（Bundles）在 Verse 中定义，可以包含不同报价的组合、同一报价的叠加，或两者的混合。与简单报价一样，捆绑包报价也有自己的价格、名称和描述，以及与权益和报价都不相同的图标。你还可以通过在捆绑包报价中包含捆绑包来嵌套报价。例如，一个限时捆绑包可以包含一把铲子和一捆玉米种子包。这样就可以把小捆绑包作为积木，搭建更大型的组合捆绑包。

标准的捆绑包类型有：

  • Stacked bundle（叠加捆绑包）：包含同一权益多个报价的捆绑包，通常以折扣价出售。
  • Multi-offer bundle（多报价捆绑包）：组合多个权益报价的捆绑包，也可以混合叠加报价和普通报价。

捆绑包包含一个报价元组数组，其中包含已定义的报价和表示报价数量的 int。

嵌套报价的深度不能超过 5，否则尝试的交易将失败。请尽量限制报价嵌套。

下面的代码片段演示了药水包捆绑包的构建。报价信息在 EntitlementInfo 模块中定义，并包含 PotionCount 变量。

ExampleOffers<public> := module:
    using {EntitlementInfo}
    # --- other offer definitions above ---
    potion_pack<public> := class(bundle_offer):
        var Name<override>:message = EntitlementInfo.PotionPack.Name

购买限制

你可以限制权益购买（restrict entitlement purchases），从而创建限定的节日物品、促销或季节性报价，以及特定地区内容。

GetMinPurchaseAge

使用 GetMinPurchaseAge 为特定的 entitlement_offer 定义自定义购买限制。它会在购买验证过程中自动调用，因此只需定义即可。可以定义具体的整数值、国家代码或平台系列。

注：Subdivision codes（二级行政区代码）目前不受支持，将在未来版本中提供。

以下是 GetMinPurchaseAge 函数的一些示例。

# Optional overrideable function you can use to inform Epic systems what the minimum age a player needs to be to purchase this offer
GetMinPurchaseAge<override>(CountryCode:string, SubdivisionCode:string, PlatformFamily:string)<decides><computes>:int =
    # A Hypothetical example where you only want to sell swords to people who don't live in Antarctica
    CountryCode <> CountryCodes.Antarctica
    return 0

玩家权益验证

玩家权益验证是确保玩家购买的权益在会话之间持久存在的必要步骤。如果没有正确验证权益，可能会导致权益重复或权益丢失等问题。

验证历史购买

下面的代码片段演示了玩家加入会话时执行的简单权益验证。首先检查新加入的玩家是否订阅了 OnPurchasesChanged 事件；如果尚未订阅，则为该玩家订阅；最后使用 ValidatePreviousPurchases 获取该玩家所有已购权益的记录。

在这一阶段对玩家权益进行验证检查也是良好实践，以确保体验中保存的数据与 Marketplace API 记录的玩家库存一致。

OnPlayerJoin(InPlayer:player):void =
    Subscription := GetEntitlementsChangedEvent(InPlayer, Entitlements.feature_example_entitlement).Subscribe(OnPurchasesChanged)
    if (set EntitlementChangeSubscription[InPlayer] = option{Subscription}):
        Print("Adding entitlement Change Subscription player subscription")

处理购买

处理权益购买的两个主要函数是 BuyOffer 和 OnPurchasesChanged。第一个函数处理向玩家展示报价并验证购买的逻辑，第二个函数处理成功交易或退款的逻辑。下面的代码片段演示了这两个函数。

# Base Implementation of how to present players with an offer to purchase in your experience
TryBuyOffer(Player:player, Offer:entitlement_offer)<suspends>:void =
    Result := BuyOffer(Player, Offer)
    if (Result?):
        # do nothing it should respond in the purchase subscription, see OnPurchasesChanged for details

处理消耗品

要消耗消耗品权益，必须使用 Marketplace Verse API 中的 ConsumeEntitlement 函数。消耗成功后，必须处理消耗后产生的效果逻辑。玩家拥有的该权益 Count 会减去函数中消耗的 Count。

下面的代码片段演示了指定玩家如何消耗特定权益。

# Base Implementation of how to flag a consumable in your experience as being consumed
TryConsumeEntitlement(Player:player, Entitlement:concrete_subtype(entitlement), NumberConsuming:int)<suspends>:void =
    Result := ConsumeEntitlement(Player, Entitlement, ?Count := NumberConsuming)
    if (Result?):
        Print("Successfully consumed entitlement!")

无法消耗耐用品权益。如果尝试这样做，ConsumeEntitlement 将失败。

授予权益

与需要 V-Bucks 的购买权益不同，你也可以使用 GrantEntitlement 方法向玩家授予权益。

授予权益的潜在用例包括促销物品、消耗品免费试用，以及因错误或故障恢复丢失的物品。

以下代码片段演示了向玩家授予权益的方法。

# Base Implementation of how to give players a entitlement in your experience without them purchasing it
TryGrantEntitlement(Player:player, Entitlement:concrete_subtype(entitlement), NumberToGrant:int)<suspends>:void =
    Result := GrantEntitlement(Player, Entitlement, ?Count := NumberToGrant)
    if (Result?):
        Print("Successfully granted a player your entitlement!")

尝试授予超过权益 Max Count（最大数量）的数量，或授予超过 1 个耐用品权益，会导致权益授予失败。

向玩家展示权益报价

Marketplace 模块提供了内置店面 UI，可在岛屿上使用 ShowOffersDialog 函数。下面的代码片段演示了向特定玩家展示包含多个报价的店面的方法。

# Base Implementation of how to show an array of offers to the player that are available for purchase
ShowArrayOfOffers(Player:player)<suspends>:void =
    ShowOffersDialog(Player, array{ExampleOffers.basic_sword{}, ExampleOffers.potion{}, ExampleOffers.potion_pack{}, ExampleOffers.potion_thanksgiving{}})
