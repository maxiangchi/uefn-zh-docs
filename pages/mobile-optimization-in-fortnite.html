移动端优化

所有 UEFN 岛屿都要适配从高端 PC 到移动设备的多种硬件。本页介绍为移动端设计时的关键考量，帮你从一开始就兼顾优化与内存效率。

英文原标题：Mobile Optimization In Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

所有 Unreal Editor for Fortnite（UEFN）岛屿都要支持多种硬件，从高端 PC 到移动设备，但要打造在移动端表现出色的岛屿，必须从一开始就考虑优化与内存效率。

本页将带你了解为移动端设计时的关键考量。

可扩展性设置

UEFN 在设计上支持平台可扩展性。由于硬件限制，一些功能在较低画质级别会被禁用或降级。使用编辑器内的 Visual Scalability（视觉可扩展性）工具，可以在不同可扩展性组下预览你的岛屿。强烈建议在多个级别下测试。

下表展示了在不同画质级别下会缩放或被禁用的关键功能：

让岛屿与资源具备可扩展性，才能在任何设备上都呈现尽可能好的性能与画面。需要考虑的关键方面有：

  • 网格体 LOD：为自定义静态或骨骼网格体使用网格体 LOD（Mesh LODs），降低多边形数量，提高每秒帧数（FPS）。
  • 世界与 HLOD：使用HLOD 与 World Partition对地图进行流送，减少渲染内容，减轻 GPU 负担，提高 FPS。
  • 纹理组与 Mipmap：通过 MIP 贴图启用运行时材质缩放。确保纹理位于正确的组中，并按2 的幂（powers of two）创建，以保证平滑缩放与视觉质量。不符合 2 的幂的纹理将无法流送。
  • 材质质量：复杂材质在低端平台上可能开销过大。我们创建了材质函数包装器，帮你针对不同平台层级进一步自定义材质的各个方面。
    导航到 Fortnite > Materials > Functions，你会找到 MF_QualitySwitch_MaterialAttributes、MF_QualitySwitch_Scalar 和 MF_QualitySwitch_Vector。使用这些质量切换包装器精简低画质设置下的材质函数，可以提高性能。更多信息请参阅材质函数（Material Functions）页面。

针对移动端优化美术与资源的技巧

  • 从一开始就注意移动端的限制。
  • 避免过度绘制（overdraw）。压平图层、限制透明、修剪重叠的杂物。
  • 简化纹理。使用压缩工具。
  • 在移动设备上充分测试你的岛屿。注意 UI 冲突，以及与 gameplay 操作重叠的元素。你可以使用 Amazon Luna 或 Xbox Cloud Gaming 来试玩移动端体验。
  • 运行内存计算（Memory Calculation）工具，获取关卡中最耗资源的详细列表。

更多优化技巧

虽然 UEFN 的引擎可扩展性非常出色，但你仍然需要精简和优化内容。硬件过载会导致 FPS 过低、加载缓慢和体验不佳。请参考以下指南提高性能：

  • 优化网格体：多边形数量保持尽可能低。多边形数量预算请参阅Fortnite 就绪资源最佳实践（Fortnite-Ready Assets Best Practices）。
  • 材质数量：使用尽可能少的材质。理想情况下每个网格体只使用一个材质分段。
  • 纹理分辨率：移动设备的纹理内存有限。使用 512x512 像素纹理，尽可能避免更大的尺寸。
  • 减少绘制调用（Reduce Draw Calls）：避免同时渲染太多独特的物体和纹理。使用实例（Instances）和分层实例化静态网格体（Hierarchical Instanced Static Meshes，HISM），并在可行时将小物体合并为更大的道具。
  • World Partition 与数据层（Data Layers）：减少屏幕上的资源与加载时间。参阅内存管理（Memory Management）文档页了解 World Partition。
  • 优化光照：使用尽可能小的光照半径，避免光照重叠，并将光照的 Mobility（可移动性）设为固定（Stationary）。
  • 对不需要锐利阴影的灯光关闭投射阴影（Turn off Cast Shadows），特别是在天光已提供足够环境光的室外区域。
  • 使用光照可扩展性管理器（Lighting Scalability Manager）：为每个 ESS 级别创建不同的光照方案。你可以为低、中级别（移动端和旧主机）设置更简化、性能更高的光照方案。

Mipmap 及其作用

可以把 Mipmap 理解为纹理的 LOD。纹理分辨率会根据相机距离和朝向切换。

虽然使用无 Mipmap 的纹理看起来更清晰很诱人，但这类纹理会一直占用设备内存，并绕过 UEFN 的流送流程。

下图展示了不同尺寸的纹理内存占用。例如，1024x512 纹理的内存占用是 1024x1024 纹理的一半。

单个纹理看似占用不大，但屏幕上会同时加载许多纹理，且相机移开后不会立即从内存清除。这种累积可能因超出内存上限而导致设备崩溃。

移动端故障排除

以下是一些常见问题及优化岛屿移动端表现的解决方法。

移动设备上帧数（FPS）过低

问题：绘制调用（draw calls）过多，显卡过载。

  • 解决方法：减少同一时间可见的内容。使用 World Partition 划分关卡，减少渲染内容。
  • 解决方法：使用 HLOD 和网格体 LOD 降低资源复杂度与多边形数量，让 GPU 更快地渲染物体。
  • 解决方法：在较低画质设置下简化复杂材质，或减少独特材质的数量——独特材质越多，每帧需要的 GPU 计算越多。尽可能复用材质。
  • 解决方法：尽可能将小物体合并为一个更大的资源。这样显卡可以把它们作为单个物品或单个绘制调用来渲染。

问题：一次加载的资源过多。

  • 解决方法：使用 World Partition 划分关卡，减少加载内容的数量。
  • 解决方法：使用 HISM 和实例（Instances）减少独特资源的数量。
  • 解决方法：尽可能复用材质，减少每帧的 GPU 计算。

岛屿内存占用过高

问题：内容未经优化。

  • 解决方法：尽可能使用 512x512 纹理，分配正确的纹理组（Texture Group），并确保启用流送。
  • 解决方法：对于自定义网格体，使用尽可能小的多边形数量，以获得有效的 LOD 并减小烘焙体积。

问题：独特网格体过多。

  • 解决方法：尽可能使用 HISM 和实例（Instances）。以不同方式复用同一资源可以减少内存中存储的独特资源数量。
  • 解决方法：尽可能将小物体合并为一个更大的资源。
