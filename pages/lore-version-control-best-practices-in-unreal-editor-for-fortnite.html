Lore 版本控制最佳实践

Lore 是 UEFN 中内置的自定义版本控制系统，用于跟踪项目更改并维护事实来源；本文介绍它的工作原理与最佳实践。

英文原标题：Lore Version Control Best Practices In Unreal Editor For Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

Lore 是虚幻编辑器 Fortnite 版（Unreal Editor for Fortnite，UEFN）中内置的自定义版本控制（version control）系统。

版本控制让个人开发者以及队友或协作者能够存储项目文件的不同版本、跟踪更改、保留项目的主要源文件，甚至在必要时回滚到更早的项目版本。

版本控制概述

版本控制与源代码管理（source control）类似，但并不完全相同。源代码管理关注基于文本的文件，而版本控制关注项目与文件的版本。

Lore 是一种稳定可靠的方式，用于跟踪对项目及单个项目文件所做的更改。版本控制会保留更改历史，记录谁在何时出于什么原因修改了哪个文件。

版本控制会记录已迁入（checked-in）文件的历史。通过迁入对项目和项目资源所做的更改，你就记录了一段历史。只要你和团队持续、定期地迁入更改，你们就会拥有一份从创建第一个文件起的完整记录。

这意味着每个 UEFN 项目都有一个基础文件，其中包含自项目文件创建、资源首次迁入之日起的项目信息。随着项目推进，文件也会在版本控制中被添加或移除。

Lore 的工作原理是：在文件被迁出（checked out）时跟踪所做的更改，将更改后的文件合并到主要源文件，并捕获项目的新版本，使其成为新的主要源文件。这就是项目的"事实来源（source of truth）"。

Lore 为你的所有项目维护一个仓库，其中包含全部历史更改以及项目的当前状态。启用 Lore 后，你可以在 UEFN 中查看历史记录并还原更改。

最佳实践

以下是一些最佳实践，可帮助你充分利用 Lore。

  • 为所有新建项目启用版本控制。
  • 每次使用 Lore 时都要定期迁入你的更改。
  • 不要在 Lore 之外启用多种版本控制方法；在文件系统的同一项目/位置上启用多个版本控制或备份系统会导致意外行为，因为两者都没有明确的事实来源可供参照。
  • 打开项目时，在进行任何更改之前，始终先同步（Sync）最新版本。
  • 协同工作时，让队友知道你迁出了哪些文件。
  • 在团队中共同商定，在迁出资源时哪位成员拥有优先权。
  • 注意观察项目及项目内对象上的版本控制视觉提示，以便识别是否有其他开发者迁出了项目或对象，从而避免冲突和错误。
  • 留意相关提醒：当有其他用户迁出资源并正在编辑项目/对象时，提醒会告诉你。
  • 将项目移交给队友编辑时，向其他开发者说明你所做的更改。
  • 如果你的更改可能与另一位开发者的工作冲突，在尝试同步项目之前，先把你所做的更改记录下来。
  • 如有必要，为资源制定编辑排期，以减少冲突和错误。
  • 不要迁出项目中的所有资源，这会阻塞其他开发者的工作。
  • 如果你计划修改项目中的某个功能或区域，请尽量提前迁出相应的文件，以避免与团队成员的更改发生冲突。
  • 在提交之前，为当前迁出的版本添加描述，提醒自己（以及他人）你对迁出的文件做了什么。
