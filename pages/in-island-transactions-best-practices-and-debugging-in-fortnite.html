岛内交易最佳实践与调试

学习岛内交易各方面的最佳实践，包括 Verse 设备用法、编码规范、图标要求，以及测试与调试店面的技巧。

前置主题

要理解并使用本页内容，请确保你已熟悉以下主题：

  • 创建物品与报价（Creating Items and Offers）

学习岛内交易各方面的最佳实践，以及测试与调试店面的技巧。

使用岛内交易 Verse 设备

岛内交易 Verse 设备包含岛内交易的模板代码，实现了 Verse API 中市场（Marketplace）模块各关键方面的实现，包括物品、报价、捆绑报价，以及利用默认商店 UI 处理购买。以这份代码为指南，可以帮你快速搭建店面。

访问该设备的步骤：

  • 前往 Verse 探索器（Verse Explorer）。
  • 右键点击你的项目名称。
  • 选择向项目添加新的 Verse 文件（Add new Verse file to project）。
  • 选择岛内交易设备（In-Island Transactions Device）。

要开箱即用这份代码，请进入 Verse 代码并编辑文件中的：

  • 物品名称
  • 描述
  • 图标

把代码中的默认名称替换为与你的权益（entitlement）和报价相匹配的名称。

编码最佳实践

你可以优化 Verse 代码，提高代码的可扩展性和岛屿的性能。

组织工作流

编程中一条常见的最佳实践是关注点分离。你希望文件和函数专注于执行特定任务，这样当项目规模增长时，未来维护起来更容易。

这样可以得到更小、组织清晰的代码文件，更易读易懂，调试也更容易。

在交易中可以这样应用，包括：

  • 把物品定义放在单独的文件中。
  • 把报价和捆绑报价放在单独的文件中。
  • 创建一个处理所有静态预定义报价的设备。
  • 创建一个只处理动态报价的设备。
  • 创建一个只处理购买的设备。

用模块组织代码

模块（Module）是原子的代码单元，可以重新分发，供多个文件使用。模块可以随时间修改，而不会破坏已使用该模块的文件中的依赖。你可以把冗长或重复的代码单元（如权益定义）分离到另一个文件，再用 using 语句导入。

使用模块的一大好处是：模块成员的变量只需要在一个地方定义一次，之后就可以通过导入模块、引用变量的方式，在不同的 Verse 代码文件之间共享同一份数据。如果出现与模块数据相关的错误，只需检查模块这一个故障点，而不必逐个检查所有使用过模块内容的地方。

下面的代码片段演示了如何在模块中为 CornSeedPacket 定义权益信息。

EntitlementInfo<public> := module: CornSeedPacket<public> := module: Name<public><localizes> : message = "Corn seed pack" Description<public><localizes> : message = "A pack of corn seeds. Opening a pack yields 10 corn seeds for planting." ShortDescription<public><localizes> : message = "Contains 10 corn seeds for planting."

EntitlementInfo 和 CornSeedPacket 都被定义为模块，这样你既可以导入全部权益信息，也可以直接访问 CornSeedPacket 的成员变量，例如它的 Name 变量。

下面的代码片段演示了如何导入 EntitlementInfo 模块来帮助定义 corn_seed_pack 权益。

注：像 Name 这样的变量无需重新键入字符串，因为你可以直接引用 CornSeedPacket 模块中的变量。这降低了出现拼写错误等视觉缺陷的风险。
Entitlements<public> := module: using { EntitlementInfo } # Using custom entitlement class to distinguish your entitlements. my_island_entitlement<public> := class<abstract><castable>(entitlement){} corn_seed_pack<public> := class<concrete>(my_island_entitlement): var Name<override> : message = CornSeedPacket.Name var Description<override> : message = CornSeedPacket.Description var ShortDescription<override> : message = CornSeedPacket.ShortDescription

using 语句需要给出指向要导入模块的文件路径。在本例中不需要文件路径，因为默认模块就在同一文件夹中。

提升岛屿性能

你可以把物品购买与发放方法定义为带 <suspends> 效果，并用 spawn 调用，从而提高体验的响应速度。

这样 TryBuyOffer 可以异步完成，而游戏逻辑的其他部分继续执行，也不会让游戏暂停等待交易完成。

TryBuyOffer(Player:player, Offer:offer)<suspends>:void= Result := BuyOffer(Player, Offer) OnButtonInteraction(Agent:agent):void= if (Player := player[Agent]): spawn{TryBuyOffer(Player, OfferType)}

图标最佳实践

游戏纹理要在游戏中正确渲染，对规格有特定要求。在 UEFN 中使用导入的图片创建纹理时，请确保源图片文件的高度和宽度都使用 2 的幂。这可以提高岛屿在各平台上的兼容性和稳定性。

2 的幂（Power of two）也用于纹理流送，在内存较小的平台上降低纹理分辨率。

纹理流送有助于：

  • 改变纹理的分辨率
  • 决定游戏加载的速度
  • 提高游戏的视觉质量
  • 节省 GPU 内存

关于 2 的幂规则和调整纹理尺寸的更多信息，请参阅调整纹理尺寸（Resizing Textures）。

关于向 UEFN 导入自定义资产的信息，请参阅导入资产（Importing Assets）。关于如何在 Verse 中公开纹理等资产，请参阅公开资产（Exposing Assets）。

测试与调试你的权益

实况编辑（Live Edit）和私人试玩（Private Playtest）会话都是调试会话。调试会话对交易、权益和报价行为有以下影响：

  • 交易不会从账户中扣除 V 币。
  • 发放和购买的权益会在调试会话结束时移除。
  • 调试会话可以使用调试命令（Debug Command）菜单。

你的报价必须在岛屿的私人版本和试玩版本上可用，并对所有队友可访问，才能在测试阶段使用。所提供的物品不视为已上线，只有岛屿发布并公开后，报价才正式上线。

访问调试命令菜单

在 PC 上按 Esc 键，或在手柄上按 Start/Options 键，再从菜单中选择调试命令（Debug Commands）选项，即可打开调试命令菜单。

商店调试命令

你可以在商店调试命令（Store Debug Commands）下找到店面的调试命令，可用命令如下：

命令名称说明
打开店面（Open Storefront）显示动态商店 UI，其中包含所有可用权益的报价，允许玩家逐个购买。这样你可以直接选择要测试的权益。
发放全部权益（Grant All Entitlements）填满该玩家的物品栏，使其拥有全部可用权益的最大数量。你还可以测试游戏内行为，检查玩家是否能在本不该获得物品的区域访问物品。
发放一个权益（Grant One Entitlement）给玩家发放每种权益各一个。一次会发放大量权益，但玩家物品栏仍有空间，可以继续测试购买非耐久权益而不达到最大数量。如果发放该权益会与 Consumable=false 或 MaxCount 冲突，则不会发放该权益。你还可以测试玩家在本不该获得物品的区域访问物品时的游戏内行为。
强制移除权益（Force Remove Entitlements）从玩家物品栏中移除其拥有的全部权益。这样可以将玩家物品栏重置，继续测试购买报价。该命令有助于测试当权益从玩家物品栏移除时 GetEntitlementsChangedEvent 的各种情况，例如当开门的钥匙卡被移除后阻止进入某区域。该命令还可以快速重置物品栏，加速测试迭代。
打印已有权益（Print Owned Entitlements）将拥有的全部权益打印到输出日志。
购买始终失败（Purchases Always Fail）默认关闭（OFF）。关闭时购买行为符合预期；开启（ON）后，无论条件是否满足成功，购买始终失败。购买始终失败有助于测试 BuyOffer 返回 false（表示购买尝试失败）时的各种情况。
