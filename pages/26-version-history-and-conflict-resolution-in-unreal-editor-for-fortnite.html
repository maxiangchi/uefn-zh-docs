分支历史与冲突解决

Lore 在分支历史选项卡中列出当前同步分支的全部已提交版本；本文介绍如何查看版本信息、回退版本、执行资产级操作，以及在冲突解决选项卡中裁决冲突。

英文原标题：Version History and Conflict Resolution in Unreal Editor for Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

Lore 会在分支历史（Branch History）选项卡中列出当前同步分支的全部已提交版本。该选项卡让你可以快速查找重要版本信息、资产冲突，并按日期筛选版本。

当你执行同步最新（Sync Latest）、迁入更改（Check-in Changes）或合并（Merge）分支时，若发现任何冲突，系统会通过弹窗消息通知你必须复核这些冲突。打开冲突解决（Conflict Resolution）选项卡，即可查看哪些资产处于冲突状态，并在视口（viewport）或关联的资产编辑器中打开各项资产更改。

复核资产更改后，从冲突解决选项卡中选择以哪一版更改作为项目的当前状态，即可轻松解决该资产冲突，并生成一个新的项目状态版本。

这些功能减少了项目阻塞，让队友可以独立解决冲突。冲突解决会在分支历史选项卡中产生一个新版本，团队成员可以在当前分支上查看全部版本。

分支历史选项卡

依次选择版本控制（Revision Control） > 查看分支历史（View Branch History），即可打开分支历史选项卡。

双击某个版本，或点击展开图标，即可打开版本详情。在这里可以查看资产及其状态，以及更改的日期与时间。

你可以开着分支历史选项卡继续工作。在选项卡顶部可以迁入更改、同步到最新版本，并按特定时间戳筛选版本。

向项目添加资产和 actor 时，迁入更改（Check in Changes）按钮会高亮。点击该按钮即可提交一个新版本，新版本会被添加到分支历史列表顶部。

点击 Rewind 图标可同步到更早的版本。

同步到最新后，若存在冲突的更改，版本左侧会出现冲突图标，右侧会显示冲突数量。

点击列表右侧的冲突项，即可查看处于冲突状态的资产。

回退到指定版本

回退到指定版本（Rewind to Revision）功能让你可以回到更早的版本，从版本历史中的某个 earlier 时间点继续工作。如果你对最近版本中的更改不满意，就可能想回退到更早的版本。

回退到旧版本会忽略从所选时间点到你当前工作版本之间所做的全部更改。

按以下步骤使用回退到指定版本：

  • 在分支历史选项卡中选择一个版本并点击 Rewind 图标。分支历史选项卡与底部工具栏会出现新的按钮选项 Restore as Latest（恢复为最新）。
  • 点击 Restore as Latest 按钮，打开 Restore as Latest 窗口。
  • 填写恢复该 earlier 版本的原因，这将作为新恢复版本的版本描述。
  • 点击窗口底部的 Restore as Latest 按钮。

分支历史中、所选时间点与新恢复版本之间的版本会变灰，被忽略的版本旁边会出现一条虚线。

你可以通过回退到某个变灰版本的方式，同步到版本历史时间线中被忽略的版本。

资产级操作

资产级操作让你可以直接在版本历史中编辑资产。展开版本以查看其中的资产，将鼠标悬停在版本列表中的某项资产上，即可使用资产级编辑工具，点击编辑图标即可使用这些工具。

各工具用途不同：

  • 在视口中聚焦该资产；
  • 在内容浏览器中打开该资产；
  • 查看资产依赖项。

版本编辑

版本编辑可以在资产层级完成，有两种方式：

  • 同步到你正在查看该资产所在的版本，以便在该版本中聚焦它；
  • 在当前同步的版本中查看该资产。

打开内容浏览器

选择在内容浏览器中打开资产，会打开内容浏览器并预先选中该资产。

查看依赖项

某些资产带有依赖项，改动它们可能会连带撤销其他资产的更改。该视图让你可以在把资产同步到过时版本、或基于该版本修改资产之前，查看全部依赖项并做出知情决策。

点击链接图标可打开依赖项查看器（Dependency Viewer），复核该资产的全部依赖项。

冲突解决

解决冲突只能在冲突解决（Conflict Resolution）选项卡中完成，该选项卡仅在你有处于冲突状态的资产时出现。可以在冲突解决选项卡中解决以下四种冲突：

  • 断开连接后离线处理资产时所做的更改；
  • 关闭自动迁出（Auto Checkout）后，未同步到最新版本、也未迁入更改就直接处理资产所做的更改；
  • 在 Windows 资源管理器中直接修改项目文件；
  • 两名队友同时修改同一份 Verse 代码。

点击同步到最新（Sync to Latest）会揭示资产冲突。当资产存在冲突时同步项目文件，会弹出更改冲突（Conflicting Changes）弹窗，点击弹窗上的 Review Conflicts 按钮即可开始解决冲突。

随后会打开冲突解决（Conflict Resolution）选项卡，你需要在其中选择保留当前更改，还是保留所冲突版本的传入更改。可以在选项卡顶部在 All Current 与 All Incoming 之间整体选择，也可以逐项选择保留 All Current 或 All Incoming 中的具体更改。

资产冲突以两张缩略图表示。在冲突列表中选中一项资产更改并点击 Reload level to preview，该资产的更改会出现在关联的资产编辑器或视口中。选定要保留的更改后，点击 Resolve Conflict。

要进一步查看每张缩略图的信息，可点击资产名称旁的展开图标打开冲突视图，每张缩略图会展开显示更多细节，简要呈现每位团队成员对该资产所做的更改。

每张缩略图上有四个图标：

  • 聚焦（Focus）图标——在视口中查找并聚焦该资产；
  • 文件夹（Folder）图标——在内容浏览器所属文件夹中显示该资产；
  • 链接（Link）图标——显示依赖项树（Dependency Tree），呈现应用于该资产的全部更改以及受该更改影响的其他资产；
  • 差异（Diff）图标——打开差异窗口对比两个版本，帮你识别差异并做出知情的裁决。

点击选项卡中资产预览窗口底部 Summary 旁的展开图标，可在冲突详情（Conflict Details）面板查看更改摘要，快速对比你与队友的更改差异。摘要会呈现以下信息：

  • 大小（Size）；
  • 资产（Asset）；
  • 更改日期（Date of change）；
  • 版本描述（Version description）；
  • 版本 ID（Version ID）。

保留我的 / 保留你的

选中代表队友更改的缩略图，点击冲突解决选项卡底部的 Reload level to preview 按钮，即可在视口中查看队友对该资产的更改，更改会出现在视口中。

在视口中查看同事对资产所做的更改时，可以使用缩略图上的图标，或打开冲突详情（Conflict Details）面板，复核该资产更改的更多信息。

点击代表你的更改的缩略图，再点击冲突解决选项卡底部的 Reload level to preview 按钮，即可查看你的更改，从而在视口中对两版资产更改做并排对比。

决定保留哪一版资产更改后，选中代表该更改的缩略图，点击选项卡底部的 Resolve Conflict 按钮，会打开版本描述窗口。简要描述本次冲突解决与被保留的版本，点击 Submit 即可把该版本加入分支历史列表。

Verse 中的保留我的 / 保留你的

Verse 冲突不会显示为缩略图，也不会出现在冲突解决列表中。在未先同步到最新版本的情况下打开 Visual Studio Code 并修改文件，若同事已先于你修改了该文件，你就会进入冲突状态。

点击 UEFN 界面底部的 Check in Changes 或 Sync Latest 会弹出冲突警告弹窗，点击 Review Conflicts 可打开冲突解决（Conflict Resolution）选项卡。

点击冲突解决选项卡中的 Resolve in VS Code 按钮，冲突的 Verse 文件会在 Visual Studio Code 的三路合并窗口中打开：左侧绿色为一方更改，右侧紫色为另一方更改，窗口底部黄色为文件的当前状态。

点击左侧、右侧与当前状态 Verse 文件更改旁的溢出菜单，会看到不同的选项。

在左侧可选择 Accept All Changes from Left 接受左侧文件的更改；在右侧可选择 Accept All Changes from Right 接受右侧文件的更改，或把左右更改分别与底部基准文件对比；在当前版本上可选择 Reset 重置文件。
