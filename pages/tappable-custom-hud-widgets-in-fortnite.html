可点击的自定义 HUD 控件

让任意自定义 HUD 控件响应触屏点击，同时兼容手柄与键盘按键：用 UMG 的自定义按钮（Custom Button）或 Verse 按钮，把快捷栏、宝石计数、奖励通知、背包图标做成可点击的，一套配置全输入模式通用。

英文原标题：Tappable Custom HUD Widgets in Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

你可以让任意自定义 HUD 控件响应触屏设备的点击，手柄或键盘上绑定的按键也能触发。用 UMG 做的自定义按钮（Custom Button）或 Verse 按钮，把快捷栏槽位、宝石计数、奖励通知、背包图标等 HUD 元素做成可点击，直接跑 Verse 逻辑。

本页讲解如何制作响应触摸输入的 UI 控件（Unreal Motion Graphics，UMG）。UEFN 用 Verse UI 与Unreal Motion Graphics 组合编写 UI。

只要 HUD 元素需要响应玩家点击，就用这套办法。常见情形：从货币计数打开商店，从通知领取奖励，从背包图标触发快捷操作。

键鼠、手柄、触屏玩家都能触发同一个动作——不用按输入模式逐个特殊处理。

原理

该功能让 Verse UI 的 button 与 UMG 自定义按钮（Custom Button）控件在 gameplay 中原生支持触摸输入。用法：给按钮指定一个触发输入动作（Triggering Input Action）。玩家与按钮交互时，输入动作触发，点燃按钮的 On Click 事件。

也就是说，快捷栏和 HUD 按钮一套配置，全输入模式通用。

让自定义 HUD 控件可点击

下面几节分别讲解用 UMG 和 Verse UI 让自定义 HUD 控件可点击。

用 UMG

  • 在 UMG 中打开 HUD 元素的用户控件。
  • 添加 Custom Button 控件（或用现有的）。
  • 在细节（Details）面板的 Input 下，把 Triggering Input Action 属性设为这次交互要触发的输入动作（Input Action）。
  • 给控件加一个 Verse Field 事件。
  • 配 UMG 数据绑定：按钮被交互时点燃 Verse Field 事件。下例中，UMG 里 4 个自定义按钮的 On Clicked 事件各绑了一个数据绑定，分别点燃各自关联的 Verse Field 事件。
  • 在 Verse 里写代码响应 Field 事件，并加上关联的映射上下文。

using { /Fortnite.com/Devices } using { /Verse.org/Simulation } using { /UnrealEngine.com/Temporary/Diagnostics } using { /Verse.org/Input } #Defines an event that can be canceled and handles canceling it. cancelable_event := class: Event:event() = event(){} Cancel():void=

用 Verse UI

  • 在 Verse UI 代码里给 HUD 加 button 控件，并指定 TriggeringInputAction。
  • 把想要的输入动作赋给按钮的 TriggeringInputAction 属性，这是 Verse 代码订阅并响应的命名事件。
  • 写 Verse 代码响应按钮的 OnClick 事件。

using { /Fortnite.com/Devices } using { /Fortnite.com/Input } using { /Fortnite.com/UI } using { /UnrealEngine.com/Temporary/Diagnostics } using { /UnrealEngine.com/Temporary/UI } using { /Verse.org/Input } using { /Verse.org/Simulation } jump_button_device := class(creative_device):

输入映射与快捷栏动作

为了让快捷栏式物品选择全输入模式通用，有个 HotbarMapping 输入上下文可用，提供预配好的快捷栏槽位组合动作：

Input<public> := module: Gameplay<public> := module: HotbarMapping<public>:input_mapping = external []

示例：物品选择的自定义快捷栏

搭建可点击快捷栏：

  • 在 HUD 控件的每个快捷栏槽位上叠一个 Custom Button 控件。
  • 通过 Verse 添加 HotbarMapping 上下文。
  • 在 UMG 里给每个按钮的 TriggeringInputAction 属性指定一个 HotbarSlot 输入动作。
  • 把每个自定义按钮的 OnClick 事件绑到 Verse 字段。
  • 在 Verse 里添加 HotbarMapping 上下文，订阅每个绑了 OnClick 事件的 Verse 字段，实现物品选择逻辑。

效果：触屏点快捷栏槽位、按手柄组合键、用键盘快捷键，点的都是同一个事件，跑的都是同一个 Verse 处理函数，不用按设备分支。

到 UEFN 的用户界面特性示例（User Interfaces Feature Example）中看自定义快捷栏示例，亲眼看看快捷栏跑起来什么样。

借用默认动作驱动自定义行为

因为自定义逻辑跑在订阅的输入动作（Input Action）上，游戏用不上的默认动作可以挪为己用。比如扔靶游戏里角色不跳，就在 Verse 里订阅默认 Jump 动作，在处理函数里写 throw ball（扔球）逻辑。默认触屏布局照样显示 Jump 按钮（玩家眼里它就是投掷键），点它就跑你的代码。

从 TouchActionWrapper 迁移

项目里如果用了 TouchActionWrapper，按以下步骤迁到自定义按钮：

  • 在 UMG 里找到拿 TouchActionWrapper 当父容器的控件。
  • 删掉 TouchActionWrapper，换成标准 Custom Button 控件。
  • 在自定义按钮控件上，把 Triggering Input Action 属性设为之前赋给 TouchActionWrapper 的 InputAction 属性的同一个输入动作。
  • 按需更新 Verse 代码，GetInputEvents / TriggerActivationEvent 订阅模式不变。
  • 保存并验证项目，全部实例替换完，编辑器里 TouchActionWrapper 的验证报错就消失了。

触屏控件定制的更多信息，请参阅开发者可定制触屏操控（Developer Customizable Touchscreen Controls）。
