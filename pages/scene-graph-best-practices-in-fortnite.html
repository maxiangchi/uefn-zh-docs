场景图（Scene Graph）最佳实践

场景图（Scene Graph）文档全面概述了其基本原理与核心概念，本页通过实例讲解你在开发项目时应遵循的最佳实践。

英文原标题：Scene Graph Best Practices in Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

注意：请学习使用这一 Beta（测试版）功能，但在正式发行（Shipping）包含该功能的项目时请谨慎。

场景图（Scene Graph）文档全面概述了场景图（Scene Graph）的基本原理与核心概念。本页的信息与示例有助于巩固这些概念，并为你在开发项目时应遵循的最佳实践（Best Practices）提供指导。

模拟实体（Simulation Entity）

模拟实体（Simulation Entity）充当场景图（Scene Graph）的根实体（Root Entity）。它对导航至关重要，也是向世界中生成新预制件（Prefab）的入口。

# Get the Simulation Entity and Spawn a prefab
if:

then:
    SpawnedPrefab:entity = LightPost.P_LightPost{}
    SimulationEntity.AddEntities(array{SpawnedPrefab})
# Set the transform for the Spawned Prefab
SpawnTransform:transform = transform:
    Translation := vector3:
        Left := -9084.0

浏览层级结构

Verse 提供了多种遍历场景图（Scene Graph）层级结构的标准方法。这些方法可用于在树中定位当前节点上方与下方的实体（Entity）。

(InEntity:entity).FindDescendantEntities<native><public>(entity_type:castable_subtype(entity))<transacts>:generator(entity_type)
(InEntity:entity).FindAncestorEntities<native><public>(entity_type:castable_subtype(entity))<transacts>:generator(entity_type)
(InEntity:entity).FindDescendantEntitiesWithComponent<native><public>(component_type:castable_subtype(component))<transacts>:generator(entity)
(InEntity:entity).FindAncestorEntitiesWithComponent<native><public>(component_type:castable_subtype(component))<transacts>:generator(entity)

你也可以用类似如下的方法，在树中向上、向下查找组件（Component）：

(InEntity:entity).FindDescendantComponents<native><public>(component_type:castable_subtype(component))<transacts>:generator(component_type)
(InEntity:entity).FindAncestorComponents<native><public>(component_type:castable_subtype(component))<transacts>:generator(component_type)

在实际 gameplay 进行期间，应避免重复执行大范围的层级结构扫描。正确做法是：用层级结构搜索 API 来发现对象间的关系，但不要在每次 gameplay 状态变化时都重复执行全树查询。更好的做法是在初始化时缓存重要引用、订阅事件，或利用预制件（Prefab）结构与标签（Tags）缩小搜索范围。

一个良好的模式如下所示：

  • 在模拟开始（Begin Simulation）时，一次性查找到所需的子组件（Component）。
  • 保存这些引用，或订阅它们的事件。
  • 之后响应事件，而不是每次都重新搜索整个图。

预制件（Prefab）组合

场景图（Scene Graph）示例项目中的 P_LightPost 预制件（Prefab）是展示预制件（Prefab）组合的绝佳范例。

在 P_LightPost 预制件（Prefab）的顶层，有一个封装了全部核心逻辑的 Verse 组件（Verse Component）。该组件负责编排路灯的行为。

Verse 组件（Verse Component）订阅了子实体（Entity）上可交互组件（interactable_component）暴露的交互事件（InteractedWithEvent）。当玩家与路灯交互时，该事件会触发顶层 Verse 组件（Verse Component）中的逻辑。

交互发生后，Verse 组件（Verse Component）会“向下调用（Call Down）”容纳特定功能组件（例如粒子系统、声音与灯光）的子实体（Entity），以执行路灯逻辑，例如：

  • 切换灯光的可见性。
  • 播放音效。
  • 激活或停用粒子系统特效。
  • 设置材质参数。

这种模式体现了清晰的关注点分离：父级 Verse 组件（Verse Component）管理高层状态与交互，而子实体（Entity）提供具体的视觉与听觉效果。

这种做法实现了明确的职责划分：父级 Verse 组件（Verse Component）处理整体状态与交互逻辑，具体的视觉与听觉效果则交给子实体（Entity）。

场景事件（Scene Events）与作用域

场景事件（Scene Events）是专为在实体（Entity）层级结构中传递事件而设计的强大事件系统。但与查询场景图（Scene Graph）层级结构一样，如果不加节制地在图的大范围中广播事件，开销也会很大。

沿祖先或后代链大范围传播的事件，可能会触发许多本无需响应的实体（Entity）上的逻辑。在大型层级结构中，这会导致不必要的事件处理并增加运行时开销。

为避免这一问题，请尽量把事件发送范围缩到最小。不要从层级结构的高层广播事件，而是从与该交互最相关的实体（Entity）或子系统发出。在可能的情况下，组织预制件（Prefab）结构，使事件在场景图（Scene Graph）的局部范围内处理，而不必遍历整个层级结构。

一般来说，场景事件（Scene Events）应遵循与层级结构查询相同的可扩展性准则：

  • 当局部化方案可行时，避免让事件穿过场景图（Scene Graph）的大范围区域。
  • 当事件范围已知时，优先使用直接引用或局部订阅。
  • 组织预制件（Prefab）结构，使大多数交互发生在其局部层级结构内。

有针对性地使用场景事件（Scene Events），有助于保持行为可预测，并确保场景图（Scene Graph）系统在项目复杂度增长时依然高效。

关于使用场景事件（Scene Events）的更多信息与细节，请参阅场景事件（Scene Events）。

Fortnite 回合管理器（Fort Round Manager）

场景图（Scene Graph）组件会在编辑模式（Edit Mode）下执行代码，这与仅在游戏模式（Game Mode）下执行的创意模式设备（Creative Devices）不同。如果你希望场景图（Scene Graph）组件代码在 Fortnite 回合开始时执行，可以订阅 fort_round_manager 的 RoundStarted 事件。

OnBeginSimulation<override>():void =
    (super:)OnBeginSimulation()
    if:
        FortRoundManager := Entity.GetFortRoundManager[]
    then:
        FortRoundManager.SubscribeRoundStarted(OnRoundStarted)

OnRoundStarted():void = ...

实体进入（Entity Entered）

场景图（Scene Graph）中的实体（Entity）能够检测与其他实体（Entity）的重叠（Overlap）。这通过 mesh_component 上的 EntityEntered 事件处理。

OnRoundStarted():void =
    if:
        Mesh := Entity.GetComponent[mesh_component]
    then:
        Mesh.EntityEnteredEvent.Subscribe(OnEntityEntered)

OnEntityEntered(OtherEntity:entity):void =
    Print("Entity Entered")

扫描（Sweep）与射线检测（Raycast）

Verse 支持扫描（Sweep）与射线投射（Ray Cast）等空间查询（Spatial Query），用于检测世界中的碰撞（Collision）。扫描（Sweep）允许你让一个形状在空间中移动，并检测它沿途碰撞到的对象。

射线检测（Raycast / Line Trace）

一个常见的困惑点是如何执行线性追踪（Line Trace）。在 Verse 中，这通过 collision_point 实现。

Displacement:vector3 = vector3{Left := 0.0, Up := 0.0, Forward := 300.0}
CollisionPoint := collision_point{}
# Line Trace Forward 300 units starting from the entity transform
for:
    Hit : Entity.FindSweepHits(Displacement, Entity.GetGlobalTransform(), CollisionPoint)
do:
    # Handle hit...

重叠查询（Overlap Queries）

重叠查询（Overlap Query）允许你检测指定位置给定形状内的全部实体（Entity）。与射线检测或扫描不同，重叠查询不会追踪穿过空间，而是检查已有体积相交的对象。

# Overlap using a custom collision volume at a specific transform
OverlapWithVolume():void =
    CollisionCapsule := collision_capsule{Radius := 36.0, Length := 328.0}
    QueryTransform := Entity.GetGlobalTransform()
    for:
        Hit : Entity.FindOverlapHits(QueryTransform, CollisionCapsule)
    do:
        # Cast the hit target to a specific component type
        if (MyMesh := my_mesh_component[Hit.TargetComponent]):
            Print("Hit mesh at: {Hit.SourceGlobalTransform.Translation}")

实体移动（Entity Movement）

keyframed_movement_component 目前是移动实体（Entity）最高效的方式，因为它会在客户端（Client-Side）更新。

拖放偏好设置

你可以启用一项编辑器偏好设置（Editor Preference），改变拖放（Drag and Drop）行为，使其在可行时优先放置实体（Entity）与组件（Component），而非 Actor。

要启用它，请从编辑（Edit）菜单打开编辑器偏好设置（Editor Preferences）。前往 Unreal Editor for Fortnite > Settings > Workflows > Drag and Drop，取消勾选 Prefer Actor Placement。

标签（Tags）

场景图（Scene Graph）中的实体（Entity）可以分配 Verse 标签（Verse Tags）。无论目标在场景图（Scene Graph）层级结构的上方还是下方，这些标签都能帮你定位并引用实体（Entity）。

你可以在细节（Details）面板中为实体（Entity）添加与移除标签（Tags）：

@experimental
# Finds all descendant entities including InEntity with Tag present in their tag_component.
# When querying from the simulation entity, the simulation entity itself is not included in the results.
# The order of the returned entities is unspecified and subject to change.
(InEntity:entity).FindDescendantEntitiesWithTag<native><public>(tag_type:castable_subtype(tag))<transacts>:generator(entity)

@experimental
# Finds all ancestor entities to InEntity with Tag present in their tag_component.
# The order of the returned entities is unspecified and subject to change.
(InEntity:entity).FindAncestorEntitiesWithTag<native><public>(tag_type:castable_subtype(tag))<transacts>:generator(entity)
