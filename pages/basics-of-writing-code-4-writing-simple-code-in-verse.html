编写代码基础 4：在 Verse 中编写简单代码

本课将学习代码注释、条件表达式与多条件判断，并真正开始编写简单的 Verse 代码。

英文原标题：Basics Of Writing Code 4 Writing Simple Code In Verse · 查看英文原文 · 社区翻译镜像，仅供学习

前置主题：要理解和使用本页内容，请确保你已熟悉以下主题：
  • 第 3 课：在 Verse 中存储和使用信息

在本课结束时，你将有机会真正开始编写简单的代码——而不只是修改已经写好的内容！

但首先，先补充一点背景知识。

优秀程序员的做法（而不是死记硬背）

经验丰富的程序员会在代码中留下一些备注，这些备注并不是程序本身的一部分，而是关于自己做了什么、为什么这样做的注释（comment）。程序运行时，这些注释会被忽略，但这些名为代码注释（code comment）（简称注释）的笔记会一直保留在代码中。

代码注释

编写代码注释总体上是良好的编程习惯，尤其当你刚开始编程、还在边学边摸索时特别有用。当你试图理解为什么你（或其他人）要这样写时，这些注释会非常有帮助。

写代码注释最简单的方法是在注释前加一个 #，不过还有其他写法：

1+2 # Hello

单行注释（single-line comment）：# 之后到行尾之间的所有内容都属于代码注释。

1<# inline comment #>+2

行内块注释（inline block comment）：<# 和 #> 之间的所有内容都属于代码注释。行内块注释可以写在同一行表达式之间，不会改变表达式的含义。

DoThis() <# And they can run multiple long lines #> DoThat()

多行块注释（multi-line block comment）：<# 和 #> 之间的所有内容都属于代码注释。多行块注释可以横跨多行。

<# Block comments nest <# like this #> #>

嵌套块注释（nested block comment）：<# 和 #> 之间的所有内容都属于代码注释，并且它们可以嵌套。当你想在测试和调试时注释掉一行中的某些表达式、又不想破坏已有的代码注释时，这种写法很有用。

<#> Here is a long description spanning multiple lines. DoThis() # This expression is not part of the indented comment

缩进注释（indented comment）：<#> 之后新起一行、并且缩进四个空格的所有内容都属于代码注释。第一个没有缩进四个空格的行不属于代码注释，同时也标志着该代码注释的结束。

使用条件语句在代码中做决策

还记得你在第 2 课中见过的 if .. else 表达式吗？它们被称为条件表达式（conditional expression）。

条件表达式（简称条件语句（conditional））就是告诉程序如何做决策的方式。

if 表达式用于判断某件事是成功（succeed）还是失败（fail）。如果成功，就运行某段代码；如果失败，则运行另一段代码。

你可以把它理解为向程序提一个只能回答是或否的问题。

在现实生活中，你一直在根据是非问题的答案做决策。比如，你困了吗？如果答案是“是”，你就去睡觉；如果答案是“否”（else），你就熬夜看动画片。

如果把这种行为写成程序，大概是这样：

var Tired: logic = false
var WhatToWatch: string = "nothing"
if (Tired?):
    set WhatToWatch = "your eyelids"
else:
    set WhatToWatch = "cartoons"
Print("You should watch {WhatToWatch}")

注意到 if 表达式里的问号 ? 了吗？这就是 Verse（Verse）程序检查 logic 类型是 true 还是 false 的方式。

嵌套

当代码嵌套（nested）时，意味着它被缩进写在 if 或 else 等关键字表达式之下。这些表达式会创建新的作用域。

作用域（scope）指的是一段代码块，在其中可以使用某些名称及其关联的值。作用域包含在一段缩进的代码块之内。

例如：

if (Tired?):
    set WhatToWatch = "your eyelids"
else:
    set WhatToWatch = "cartoons"

set WhatToWatch = "your eyelids" 这一行缩进在 if (Tired?): 之下。else: 之下的一行也是同样的模式。

你可以嵌套单行代码，也可以嵌套代码块（block）（多行）代码。

这意味着，当代码运行时，被嵌套的代码只会在它所从属的代码上下文中执行。

使用多个条件

有时你需要先问不止一个问题才能做决策。在 Verse（Verse）中，这要用到运算符 and 和 or，它们被称为决策运算符（decision operator）。

使用 and 时，运算符两侧的条件必须都为真（或都成功），整个表达式才算成功。

使用 or 时，只需要其中一个条件为真（或成功），整个表达式就算成功。

第一个条件运算符第二个条件整个表达式
成功and成功成功
成功and失败失败
失败and失败失败
成功or成功成功
成功or失败成功
失败or失败失败

来看一个实际例子。即使你不困，如果明天要上学，早点睡可能也是个好主意。我们创建一个名为 SchoolTomorrow 的变量，并用 or 同时检查两个 logic 变量。

var Tired: logic = false
var SchoolTomorrow: logic = true
var WhatToWatch: string = "nothing"
if (Tired? or SchoolTomorrow?):
    set WhatToWatch = "your eyelids"
else:
    set WhatToWatch = "cartoons"
Print("You should watch {WhatToWatch}")

Tired 仍然是 false，但因为 SchoolTomorrow 是 true，整个表达式成功，WhatToWatch 会被设为 "your eyelids"。

还有另一种检查多个条件的方法。

使用 if … else if … else 可以把要检查的内容排成序列。也就是说，只有当前一个条件失败时，才需要检查下一个条件。

如果明天不用上学、你也不困呢？也许你想和朋友去看电影。我们再改一次代码，看看这是怎么工作的。

更新 SchoolTomorrow 变量的值，并声明一个新变量 FriendsAvailable。

var FriendsAvailable : logic = true
set SchoolTomorrow = false

接下来，你要更新代码——只有在“不困、明天也不上学”的情况下，才去检查朋友是否有空。

if (Tired? or SchoolTomorrow?):
    set WhatToWatch = "your eyelids"
else if (FriendsAvailable?):
    set WhatToWatch = "a movie with your friends"
else:
    set WhatToWatch = "cartoons"

太棒了！现在只有在你困了、或者明天要上学时才会睡觉。如果这两个问题的答案都是否定的，那你不是和朋友去看电影（如果朋友有空），就是待在家里看动画片（如果朋友没空）。

多亏了 Verse（Verse），规划你的夜晚生活一下子变得容易多了。

故障排除

还记得在第 1 课中学过的编译器错误（compiler error）吗？

写代码时你还会遇到另一种东西：错误（bug）。

错误

错误（bug）指计算机程序中导致其产生不正确或意外结果的差错。错误的影响可大可小：小到消息文字颜色变了，大到文字消息在错误的时机显示在屏幕上，甚至导致程序崩溃。

这个术语因计算机科学先驱格蕾丝·霍珀（Grace Hopper）而流行：她在一台计算机里发现了一只飞蛾，并把它贴进手写的故障排除日志，旁边写着“发现的第一例真正的 bug”。

编译器错误会阻止程序编译，而错误要等到程序运行时才会暴露出来。

识别并清除错误的过程叫调试（debugging），帮助查找错误的工具叫调试器（debugger）。

总结

  • 用代码注释记住你为什么要这样写代码，也帮助其他程序员理解你做了什么、为什么这样做。
  • 对在整个程序中应保持不变的值使用常量。
  • 对需要根据输入变化的值使用变量。
  • 错误和编译错误都是由代码中的差错引起的。

  • 第 4 课：练习时间！在这个动手练习中，你将亲自写一些代码，并在它没有按预期工作时进行调试！
