Lore 版本控制

Lore 是 UEFN 内置的版本控制：用修订版本守护事实来源，支撑团队协作与质量把控。

英文原标题：Lore Version Control in Unreal Editor for Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

Lore 是由 Epic Games 维护的新一代开源版本控制工具，它驱动着 UEFN 的编辑器内置版本控制系统。

Unreal Editor for Fortnite（UEFN）把版本控制（version control）集成为项目管理、团队流程与质量把控的重要一环。它为项目与开发者维护唯一的事实来源（single source of truth）。

在团队项目中启用 Lore，可以促进团队成员之间的协作，避免工作成果丢失，并通过缩短制作时间来加快岛屿（island）的上线。把项目同步（synchronization）纳入日常迭代需要一点投入，但最终非常值得。

关于 Lore 版本控制的更多信息，见 Lore.org。

Lore 的工作原理

UEFN 中所有新建的岛屿都开箱自带 Lore。它的原理是在不同时间点逐步保存岛屿及其资产的状态，这些增量保存点称为“修订版本（revisions）”。

为新项目启用版本控制：在项目默认设置（Project Defaults）面板中选择 Lore，即可为该项目启用版本控制。

从团队选择（Team Selection）下拉菜单中，独自开发请选择仅自己（Only Me），团队项目请选择你的团队名称。个人项目也可以禁用 Lore。

使用 Lore 的项目托管在服务器（servers）上。

你也可以在大纲视图（Outliner）面板中使用 Lore：资产的版本控制状态会显示在资产所在行右侧，供参考；你还可以右键大纲视图中的资产，从下拉菜单选择版本控制（Revision Control）> 检出（Check out）。

在项目中使用 Lore

创建新项目时启用版本控制，会在底部工具栏增加以下功能：

  • 版本控制（Revision Control）
  • 同步更改 / 已是最新（Sync Changes / At Latest）
  • 签入更改 / 无更改（Check-in Changes / No Changes）

所有 Lore 功能都显示在项目细节（Details）面板下方。

版本控制

版本控制指示器：绿色对勾表示该项目正在使用版本控制。点击箭头打开控制菜单，在此检出修改过的文件与资产，并更改版本控制设置。

从下拉菜单点击更改版本控制设置（Change Revision Control Settings…）可更改控制设置，随后打开版本控制登录（Revision Control Login），在此开关自动设置，并查看版本控制日志（Revision Control Log）。

自动检出

新建项目时自动检出（Auto Checkout）默认开启：当你在视口中更改或移动资产时，该功能会自动把资产检出给你。

该功能会锁定你改动的资产，在你检出期间阻止其他队友修改同一对象。在大纲视图中浏览资产，可以看到哪些资产（assets）正被同事检出。

使用自动检出可以避免冲突，让你和队友以尽可能小的摩擦协作。

如果关闭了自动检出，Lore 会要求你连回网络，或保存在本地。

自动还原

自动还原（Auto Revert）会在你改动已被他人检出的资产时自动撤销你的更改，从而阻止你与团队成员产生冲突。你会收到冲突与更改被还原的警告。

该功能可以避免你在一件资产上投入数小时，最后却不得不撤销全部更改。在大纲视图中快速查看，就能知道队友正在处理哪些资产。

同步更改

该功能拉取项目的最新版本并同步到磁盘。当你看到 Sync Latest（同步最新）时，就需要同步到最新的项目版本；如果没有可同步的更改，按钮会显示 At Latest（已是最新）。

点击 Sync Latest 后，最新的项目版本会被拉取到你的本地环境，你可以在此继续工作。

只要你的更改与最新版本中的更改不冲突，且改动的不是正被他人检出的资产，即使没有同步到最新版本，也可以照常改动与保存。

可能遇到的冲突类型，详见Lore 版本控制中的冲突。

签入更改

签入所有更改，并用所有已签入的更改创建新的项目版本。当项目中有需要签入的更改时，按钮会从无更改（No Changes）变为签入更改（Check-in Changes）。

Lore 会跟踪 UE 生态原生格式源文件的版本历史，但不跟踪其他软件原生格式（如 Blender、Photoshop 等）源文件的版本历史。

点击 Check-in Changes 会打开签入更改窗口。在提交对话框的更改列表描述（Changelist Description）中列出对资产的更改，点击提交（Submit）即可创建岛屿的新修订版本。

如果签入列表中有某一项应该还原到早期版本，可以在提交窗口中直接操作。

选中资产并右键，出现带有还原（Revert）选项的下拉菜单，点击 Revert 即可撤销对该资产的更改。

  • 更改列表描述（Changelist Description）：描述你对检出资产所做的更改。
  • 加号（Plus Sign）：新增到 Lore 的资产。
  • 对勾（Checkmark）：已检出的资产。
  • 保持文件检出（Keep Files Checked Out）：选中后，即使提交了更改，文件仍保持检出给你。
  • 提交（Submit）：把更改提交到 Lore。
  • 取消（Cancel）：取消提交新版本，回到项目。

更改保存并提交成功后，队友就可以同步到新的项目版本了。项目缩略图会对所有团队成员更新，缩略图上的下载图标会提醒他们项目需要同步。

保存项目与签入更改是两回事：保存项目是把项目存到你的磁盘，签入更改是创建一个某个时刻的共享项目版本，你或任何协作者日后都可以回到该版本。

这些修订版本为项目资产提供了历史记录，日后可以据此了解资产是何时、因何、被谁修改的。

检出项目资产

检出资产（asset）会锁定该资产，阻止其他队友编辑。谁先检出对象，在检出期间谁就拥有它的控制权。

检出单个资产：

  1. 右键资产缩略图，打开资产菜单。
  2. 选择版本控制（Revision Control） > 检出（Check Out）。

资产现在已检出给你，资产缩略图上会更新出红色对勾。队友会在缩略图上看到不同的图标，从而知道该资产已被检出。

对象签入后，凡是有项目访问权限的人都需要同步到最新项目版本，才能编辑该资产。

在右键菜单中你还可以：

功能说明
同步并检出（Sync And Check Out）同步你的项目并检出该资产。
标记为添加（Mark For Add）把资产标记为要添加到项目。
历史（History）打开窗口，显示所选资产或项目的编辑历史。
功能说明
还原（Revert）把所选文件还原到之前的状态。
合并（Merge）把选中的两个资产文件合并。
刷新（Refresh）刷新所选资产的状态。
