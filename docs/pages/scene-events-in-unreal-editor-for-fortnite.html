UEFN 中的场景事件（Scene Events）

使用场景事件在场景图中自上而下或自下而上传递信号，让实体与组件之间通过消息解耦通信。

英文原标题：Scene Events in Unreal Editor for Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

场景事件（Scene events）提供了一种沿场景图向上或向下发送信号的方式。它的核心思想是解耦场景图的各个部分，让它们通过消息而非直接绑定来相互通信。

你定义一个自定义事件，从某个实体发出，沿途的任何组件都可以通过重写 OnReceive 来响应。

  • SendDown 把事件从一个实体开始，向下穿过它的子实体、孙实体等逐层传递（深度优先）。
  • SendUp 把事件向上穿过它的父实体、祖父实体等，一路传向根节点。

多个组件可以响应同一个场景事件。实体层级中每个组件的 OnReceive 都会被调用。组件可以消耗（consume）该事件（返回 true）以停止传播，也可以放行（返回 false）让它继续传递。

你需要的三样东西：

  • 自定义事件：继承自 scene_event 的类。
  • 响应组件：重写 OnReceive，对事件做类型转换并作出反应。
  • 发送调用：Entity.SendDown(Event) 或 Entity.SendUp(Event)。

场景事件可以在你的项目中复用，你可以通过添加额外事件，或微调一连串事件中实体与组件的行为，让它们实现略有不同的效果，从而扩展场景事件的用途。

类型转换模式（Cast Pattern）

OnReceive 调用提供了一种创建通用 scene_event 的方式。要弄清楚实际发送的是哪种具体类型，请使用可失败的类型转换：

if (SpecificEvent := my_event[E]):  # 转换成功 —— 可访问 SpecificEvent.Amount 等字段

如果该事件不是这个类型，转换会失败，if 代码块会被跳过。这样就能只过滤出你需要的事件。由于场景事件经过层级时，每个 OnReceive 都会被调用，因此这种类型转换必不可少。

事件传播

SendDown 事件按深度优先遍历：先调用起始实体上每个组件的 OnReceive，再递归进入第一个子实体（及其子实体），然后移向下一个兄弟实体。

SendUp 事件的遍历方向与 SendDown 相反：先从实体自身开始，再到父实体、祖父实体，一直到根节点。

如果有任何组件消耗了事件（OnReceive 返回 true），两种事件都会立即停止传播。两者都返回 logic——如果事件在某处被消耗则为 true，如果走完全程未被消耗则为 false。

被消耗的事件（Consumed Events）

  • 从 OnReceive 返回 true——传播停止，层级中后续实体不再响应该事件。

当某个组件完整处理了事件、不需要层级中其他组件再响应时，这种方式很有用。例如，护盾在伤害触及下方实体之前先吸收掉它。

damage_event<public> := class(scene_event):
    Amount<public> : int

# 吸收全部伤害、阻止其传向子实体的护盾。
shield_component := class(component):
    var ShieldHP : int = 100
    OnReceive<override>(E : scene_event) : logic =
        if (Dmg := damage_event[E]):
            set ShieldHP -= Dmg.Amount
            return true
        (super:)OnReceive(E)

如果护盾实体是生命值实体的祖先，SendDown 会先命中护盾。因为护盾返回 true，生命值组件不会受到该事件影响。

放行事件（Pass Through Events）

  • 返回 false（默认值）——事件继续在层级中传递。

component 上的基础 OnReceive 返回 false，因此在重写末尾调用 (super:)OnReceive(E) 是把事件继续向下传递的标准写法。

场景事件示例

以下是基础场景事件行为的代码示例。

定义事件

my_event<public> := class(scene_event):
    Amount<public> : int

在组件中响应事件

my_responder := class(component):
    var Score : int = 0
    OnReceive<override>(E : scene_event) : logic =
        if (Event := my_event[E]):
            set Score += Event.Amount
        (super:)OnReceive(E)

发送事件

Event := my_event{Amount := 10}
MyEntity.SendDown(Event)

处理多种事件类型

OnReceive<override>(E : scene_event) : logic =
    if (DmgEvent := damage_event[E]):
        # 处理伤害……
    else if (HealEvent := heal_event[E]):
        # 处理治疗……
    (super:)OnReceive(E)

用 var 字段从响应者收集信息

my_event<public> := class(scene_event):
    I<public> : int
    var Activations : int = 0  # 响应者可以累加该字段

# 在响应者中：
OnReceive<override>(E : scene_event) : logic =
    if (CE := my_event[E]):
        set CE.Activations += 1
    (super:)OnReceive(E)

注意事项

  • 始终调用 (super:)OnReceive(E)，确保超类的 OnReceive 被执行。
  • 对于直接继承自组件的类，这一点相对不那么重要。这种情况下，在函数末尾返回 false 以继续传播是合理的。
  • 访问字段前务必先做类型转换。参数类型是 scene_event，而不是你的具体事件类。
  • 不要意外消耗事件。返回 true 会让层级其余部分悄无声息地收不到该事件。
  • 实体必须位于场景中，SendUp/SendDown 才能工作。该限制未来可能解除。

API 速查

API作用
scene_event接口。继承它即可创建自己的事件类型。
Entity.SendDown(E)把事件发送给该实体及其所有后代。
Entity.SendUp(E)把事件发送给该实体及其所有祖先。
Component.SendDown(E)从该组件所在实体向下发送事件。（为保证兼容性，请尽量使用 Entity.SendDown/Up）
OnReceive(E):logic重写以响应事件。返回 true 表示消耗，返回 false 表示放行。
