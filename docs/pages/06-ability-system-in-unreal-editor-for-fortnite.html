能力系统 Ability System

用 Verse 构建可扩展、可复用的玩法能力：能力上下文、能力定义、效果组件与治疗能力完整示例。

英文原标题：Ability System in Unreal Editor for Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

能力系统（Ability System）是一个用 Verse 创建可扩展、可复用玩法能力（gameplay abilities）的框架。有了它，你可以创建赋予玩家魔法技能、超级能力或其他特殊能力的玩法能力。

开始之前，你应当熟悉场景图（Scene Graph），包括实体（entities）、组件（components）与预制件（prefabs）。

能力 API（Ability API）是一个用 Verse 创建可复用玩法能力的框架。它将能力激活（activation）、运行时数据（runtime data）、玩法逻辑（gameplay logic）与生命周期管理（lifetime management）拆分为不同的层，使能力易于扩展与复用。

核心概念（Core Concepts）

每个能力由四个部分组成：

  • 能力上下文（Ability Context）：存储单次激活的数据。
  • 能力（Ability）：定义能力及其需求，校验激活条件，并创建效果。
  • 能力效果（Ability Effect）：代表生成的玩法实体。
  • 能力效果组件（Ability Effect Component）：控制效果的行为与生命周期。

将能力激活、运行时数据、玩法逻辑与生命周期管理拆分为不同的层，使能力易于扩展与复用。因此，你无需重复代码即可创建同一能力的多种变体。

下表对比了自定义能力的各组成部分：

类型（Type）职责（Responsibility）生命周期（Lifetime）
ability_context存储单次激活的数据单次激活（Per Activation）
ability定义能力并控制激活持久（Persistent）
ability_effect生成的玩法实体瞬态（Transient）——每次调用效果都会创建新实例
ability_effect_component控制效果的行为与生命周期随效果存在（Effect Lifetime）

能力上下文（Ability Context）

ability_context 是临时容器，用于存放与单次激活相关的上下文数据。

基础上下文（base context）提供：

  • Instigator——负责激活能力的智能体（agent）。
  • Participants——与能力相关但并非直接目标的实体，例如武器、背包物品或其他玩家。
  • Targets——接收能力效果的实体。

上下文可以通过子类化携带更多玩法数据：

heal_context := class(ability_context):
    HealPerTick : float = 5.0

能力（Ability）

ability 是持久化定义，规定能力何时可用，并在给定上下文中创建玩法效果。

能力会存储其期望的上下文与效果类型的引用。这在整个激活流程中提供了类型安全，意味着类型不匹配会在开发阶段就被发现，而不是等到游戏中才暴露。

heal_ability := class(ability(heal_context, heal_effect)):

能力负责：

  • 对照一系列限制校验激活，例如冷却（cooldown）或资源消耗（resource cost）。
  • 创建上下文（context）。
  • 创建效果（effect）。
  • 跟踪激活中的效果（active effects）。
  • 广播开始与结束的生命周期事件。

校验激活（Validating Activation）

重写 CanUse() 即可决定能力是否可以激活。

典型检查包括：

  • 冷却（Cooldowns）。
  • 法力或资源消耗（Mana or resource costs）。
  • 目标校验（Target validation）。
  • 已存在的激活效果。
  • 游戏专属需求。
CanUse<override>(AbilityEffectParent:entity, AbilityContext:heal_context)<reads><decides>:void = (ActiveEffects.Length = 0)

Use() 会在创建效果之前自动调用 CanUse()。

创建上下文与效果（Creating Contexts and Effects）

能力通过重写两个工厂函数来创建它所使用的对象。

MakeContext() 构造传递给效果的上下文：

MakeContext<override>()<transacts>:heal_context = heal_context{ HealPerTick := 5.0 }

MakeAbility() 构造将执行玩法逻辑的效果实体：

MakeAbility<override>()<transacts>:heal_effect = heal_effect{}

激活能力（Activating an Ability）

激活能力的步骤：

  • 构造上下文。
  • 填充所需数据。
  • 调用 Use()。
HealContext := heal_context{ Instigator := option{PlayerAgent} Participants := array{} Targets := array{PlayerEntity} HealPerTick := 10.0 }

Use() 会校验请求、创建效果、绑定上下文、将效果添加到父实体（Parent entity），若激活成功则返回新创建的效果实体。

结束能力（Ending an Ability）

当能力正常完成时调用 EndUse()：

EndUse(false)

重写 OnEndUse() 即可执行清理：

OnEndUse<override>(Reason : ?cancel_reason)<transacts> : void =
    # Cleanup: unbind events, remove visual effects, etc.
    return

取消能力（Cancelling an Ability）

能力也可以通过取消来结束。

通过子类化 cancel_reason 创建自定义取消原因：

sprint_cancel := class(cancel_reason):

外部系统可以通过 Cancel() 请求取消。

重写 CanCancel() 即可决定能力是否可以被取消：

CanCancel<override>(Reason : cancel_reason)<transacts><decides> : void = true?

治疗示例中，玩家一旦开始疾跑（sprinting），治疗能力就会自行取消。

能力事件（Ability Events）

能力暴露了事件，允许外部系统观察其生命周期：

  • BeginUseEvent
  • EndUseEvent

能力还维护一个 ActiveEffects 列表，其中包含每个正在运行的效果实例。可利用它实现诸如限制同时存在的效果数量等行为。

能力效果与效果组件（Ability Effect and Effect Component）

ability_effect 是瞬态生成的玩法实体。该效果通常定义为预制件（prefab），并挂载合适的视觉、音频及其他支撑组件。

ability_effect_component 挂载在 ability_effect 实体上，控制效果的运行时行为与生命周期。效果组件还可以访问相关的能力与上下文。

该组件可以访问：

  • 激活上下文（activation context）。
  • 来源能力（originating ability）。
  • 效果生命周期（effect's lifecycle）。
heal_effect_component := class(ability_effect_component):

效果生命周期（Effect Lifetime）

重写 OnBeginUse() 即可在玩法开始前执行初始化：

OnBeginUse<override>()<transacts>:void = if (HealContext := heal_context[Context?]): set HealPerTick = HealContext.HealPerTick

OnBeginUse() 要求目标 ability_effect 已被添加到模拟（simulation）中的父实体，才能在游戏中运行。

长期运行的行为通常在 OnSimulate() 中执行：

OnSimulate<override>()<suspends>:void = loop: Sleep(TickInterval) # Gameplay logic.

治疗示例会周期性地为每个目标回血，直到持续时间结束。
