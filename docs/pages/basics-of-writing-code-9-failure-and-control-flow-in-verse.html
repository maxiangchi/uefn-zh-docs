Verse 代码基础 9：失败（Failure）与控制流

失败并不可怕，它是编程的重要组成部分。本课学习 Verse 中的可失败表达式（failable expression）与失败上下文（failure context），用失败来控制程序的行为。

英文原标题：Basics Of Writing Code 9 Failure And Control Flow In Verse · 查看英文原文 · 社区翻译镜像，仅供学习

前置知识：要理解和使用本页内容，请先熟悉以下主题：第 8 课：输入、参数与实参的工作原理（Lesson 8: How Input, Parameters, and Arguments Work）。

失败（failure）可能让人害怕，但它是编程的重要组成部分。你可以利用失败来学习如何调试、找到程序的边界，或快速看清不该怎么做！

失败也没关系

在 Verse 中，失败（failure）有着特定的含义，它并不总意味着“某件事没做成”，而是一种控制程序行为的方式。

还记得在第 4 课（Lesson 4）中学过的吗？你可以编写代码来问一个是或否的问题：

var Tired: logic = false
var WhatToWatch: string = "nothing"
if (Tired?):
    set WhatToWatch = "your eyelids"
else:
    set WhatToWatch = "cartoons"
Print("You should watch {WhatToWatch}")

上面代码中，提出问题的那部分写成了一个可失败表达式（failable expression）。在上面的例子中，Tired? 就是一个可失败表达式。

可失败表达式用于避免可能导致程序彻底停止工作的错误。例如你可能知道，除数不能为零，如果在代码里这样做，程序可能会崩溃！但下面这段 Verse 代码却可以正常运行。

if (5/0):
    Print("Whoa!")
else:
    Print("You can't do that!")

为了避免这类错误，Verse 要求你把可失败表达式写在失败上下文（failure context）中。失败上下文为可失败表达式提供了一个可以安全失败的场所。在上面的例子中，5/0 是可失败表达式，而 if() 就是失败上下文。继续阅读，深入了解 Verse 的这两个概念。

可失败表达式

在 Verse 中，可失败表达式有多种写法。如果一个表达式是在问一个“是或否”的问题，那它很可能就是可失败的。

以下是可失败表达式会问的几类问题：

  • 这两个变量谁更大、谁更小，或是否相等？
  • 这个变量是否被设为了 true？
  • 这个变量是否被赋了值？
  • 这个表达式是否会引发错误？

如果其中任何问题的答案是是，表达式即成功（succeeds）；如果答案是否，表达式即失败（fails）。成功或失败之后会发生什么，取决于你如何编写代码。

比较表达式

比较表达式（comparison expression）使用 <（小于）、>（大于）或 <>（不等于）等比较运算符，是可失败的。在下面的例子中，5 < 4 是一个会失败的可失败表达式：

if (5 < 4):
    Print("This will never print.")

表达式 5 < 4 就像在问“5 小于 4 吗？”。答案是否，表达式失败，代码块（缩进在 if 表达式下方的部分）不运行。

再看下一个例子，可失败表达式 MousetrapsSet <> MiceCaught 在问“MousetrapsSet 和 MiceCaught 的值不相等吗？”。

MousetrapsSet := 3
MiceCaught := 0
if (MousetrapsSet<>MiceCaught):
    Print("Need more cheese!")

这一次问题的答案是是，因为 MousetrapsSet 是 3 而 MiceCaught 是 0，所以表达式成功，代码块会运行。

判定表达式

使用 and、or 和 not 运算符的判定表达式（decision expression）也是可失败的。在下面的例子中，MousetrapsForSale > 0 and Coins >= MousetrapCost 是一个会成功的可失败表达式，因为 MousetrapsForSale 是 5（大于 0），Coins 是 30 而 MousetrapCost 是 20（30 大于 20）。两边的表达式各自都成功，所以整个表达式成功。

MousetrapsForSale := 5
MousetrapCost := 20
Coins := 30
if (MousetrapsForSale > 0 and Coins >= MousetrapCost):
    Print("You can buy mouse traps.")

查询表达式

查询表达式（query expression）也是可失败的。它们使用 ? 运算符检查某些值，例如检查一个 logic 值是否为 true。在下面的例子中，MousetrapStoreOpen? 是一个会失败的可失败表达式，因为 MousetrapStoreOpen 是 false。

var MousetrapStoreOpen : logic = false
if (MousetrapStoreOpen?):
    Print("Come on in!")

失败上下文

在上面所有的代码示例中，if 表达式就是其 () 内可失败表达式的失败上下文。失败上下文为可失败表达式提供了一个可以安全失败的场所，因为它决定了失败时接下来会发生什么。

从之前的课程你已经知道：当 if 中的表达式失败时，if 代码块内的代码不会运行。

因为 if 会创建失败上下文，你可以在它的代码块中放入任意多个可失败表达式。如果其中任何一个表达式失败，代码块中排在前面的表达式会被撤销，即回滚（rolled back）。

还有一种不使用 () 的 if 写法。当你需要写很多表达式时，这种写法更方便。示例如下：

MousetrapsSet:int = 5
var MiceCaught:int = 0
var BreakTime:logic = false
if:
    MousetrapsSet > 0
    set BreakTime = true
    MiceCaught > 0
if (BreakTime?):
    Print("Catch some mice!")

失败上下文中的表达式不一定都得是可失败的，但至少要有一个。在上面的例子中，set BreakTime = true 不是可失败的，其他表达式是。

在上面的代码中，所有缩进在 if 下方的表达式都在失败上下文之内，三个表达式都会执行。

  • MousetrapsSet > 0 会成功。
  • 表达式 set BreakTime = true 会执行，它不可失败，所以不做失败检查。
  • 但 MiceCaught > 0 会失败。

由于出现了失败，if 代码块中的每个表达式都会被回滚，包括 set BreakTime = true，就好像这段代码从未运行过一样。运行这段代码，你会看到打印出了“Catch some mice!”。

编程时你会发现，很多代码只有在其他代码成功运行的前提下才能工作，这也是失败上下文如此有用的另一个原因。把相互依赖的代码放进失败上下文，可以避免一些常见 bug。还记得第 4 课中用来决定是否去看电影的代码吗？现在你已经决定和朋友们一起去了，还得给他们买票、买饮料和零食！

var Drinks:int = 4
var Snacks:int = 4
var Tickets:int = 3
var FriendsAvailable:int = 4
if:
    Drinks >= FriendsAvailable
    set Drinks -= FriendsAvailable
    Snacks >= FriendsAvailable
    set Snacks -= FriendsAvailable
    Tickets >= FriendsAvailable
    set Tickets -= FriendsAvailable

运算符 -= 是减法与赋值结合的简写。在上面的例子中，set Tickets -= FriendsAvailable 等价于 set Tickets = Tickets - FriendsAvailable。加法（+=）、乘法（*=）和除法（/=）也有同样的简写。

你的饮料和零食够分给到场的朋友，但票不够。这意味着你和朋友们看不成这场电影了。你也许会写一些代码来处理这种情况，但你大概不想把饮料和零食先分出去。

幸运的是，当表达式 Tickets >= FriendsAvailable 运行时会失败，if 代码块中的所有代码都会回滚。这意味着 Drinks 和 Snacks 变量都会回到值 4。

总结

  • 在 Verse 中，失败（failure）是一种控制程序的方式。
  • 可失败表达式（failure expression）可能成功也可能失败，必须写在失败上下文中。成功或失败之后会发生什么，取决于你的代码写法。
  • 失败上下文（failure context）为可失败表达式提供了一个可以安全失败的场所。失败上下文内的任何失败，都会导致该上下文中的所有代码回滚，就像从未运行过一样。
