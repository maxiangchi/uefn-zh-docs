创建物品与商品

岛内交易让你能够使用 Verse，在岛屿上营销物品、商品与捆绑包商品。本指南将教你设置自己的物品、商品与捆绑包，并使用 Verse API 的市场模块处理游戏内物品的销售。

英文原标题：Creating Items and Offers in Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

岛内交易让你能够使用 Verse，在你的岛屿上营销物品、商品与捆绑包商品。

在本指南中，你将学习如何设置自己的物品、商品与捆绑包商品，并使用 Verse API 中的市场(Marketplace)模块处理游戏内物品的销售。

物品(Items)

在 Verse 中，物品被定义为权益(entitlement)，分为两类：消耗型物品(consumable items)，使用后会从玩家物品栏中移除；耐久型物品(durable items)，玩家可以反复使用而不会从物品栏中移除。

每个 Verse 权益都包含以下属性：

  • 名称(Name)：权益名称，最多 50 个字符。
  • 描述(Description)：与权益一同展示的长描述，最多 500 个字符。
  • 短描述(ShortDescription)：在较小对话框中概述权益的短描述，最多 100 个字符。
  • 图标(Icon)：权益的图片。

如果你的权益是付费随机物品(paid random item)，必须在描述中包含玩家可能获得内容的准确数字概率。更多信息请参阅付费随机物品。

Verse 权益还可以包含以下可选属性：

  • 最大数量(MaxCount)：玩家在同一时间可拥有的该权益的最大数量。
  • 消耗品(Consumable)：若设为true，该权益可被消耗，每使用一次总次数减一；若为false，该权益为永久物品，使用时不会被消耗。
  • 付费区域(PaidArea)：若设为true，该权益提供付费墙后区域的访问权限。
  • 付费随机物品(PaidRandomItem)：若设为true，这些权益通过购买或兑换内容来获得随机奖励。
  • 对玩法有实质影响(ConsequentialToGameplay)：若设为true，该物品为你的岛屿带来有意义的优势。详情请参阅对玩法有实质影响。

如果你有未使用的有效权益，却未在 IARC 问卷中确认应用内购买，你的岛屿将无法通过审核。

变通方法是：在 Verse 中将权益注释掉，直到你准备好在正式游戏中启用。注释掉权益后，就无需在 IARC 问卷中申报应用内购买。

在 Verse 中创建耐久型权益

Verse 中的耐久型权益与消耗型权益格式相同，但有一个关键区别——Consumable设为false而非true。耐久型权益玩家只能购买一次，且每种耐久型权益只能拥有一个。

本例将创建一把铲子作为耐久型权益，铲子纹理图标附在代码片段之后。

Shovel<public> := module: Name<public><localizes>: message = "Shovel" Description<public><localizes>: message = "An unbreakable shovel used to dig holes for planting." 默认情况下，物品不是Consumable（消耗品），且MaxCount（最大数量）为1。如果物品属于付费区域、付费随机物品，或带来有意义的、对玩法有实质影响的优势，必须在代码中定义相关字段。

权益验证规则

Verse 中的有效权益必须遵循以下准则，不符合的权益购买将会失败。

定义有效权益的规则如下：

  • 名称(Name)字符上限为50。
  • 描述(Description)字符上限为500。
  • 短描述(ShortDescription)字符上限为100。
  • 当Consumable=false时，MaxCount必须为1。
  • MaxCount最大值为10,000,000。

将MaxCount < 1不会被强制拦截，但会失败，因为你无法向玩家授予少于一件的物品。

权益目录

你可以使用权益目录(Entitlement Catalog)查看向玩家提供的所有权益。

在 UEFN 中点击工具(Tools) > 权益目录(Entitlement Catalog)，即可查看列出权益的报告；也可直接在创作者门户(Creator Portal)中对应岛屿的目录里查看。

商品(Offers)

商品(Offer)规定了某件物品或资产以V-Bucks计价的价格。每个商品都有独立于权益规格的名称、描述与图标。商品在 Verse 中定义。

每个商品包含以下属性：

  • 名称(Name)：商品名称。
  • 描述(Description)：与商品一同展示的长描述。
  • 短描述(ShortDescription)：在较小对话框中概述商品的短描述。
  • 图标(Icon)：商品的图片。
  • 权益类型(EntitlementType)：商品所含权益的声明。
  • 价格(Price)：以 V-Bucks 计价的价格，不得低于 50 V-Bucks，不得高于 5000 V-Bucks，且必须为 50 的倍数。

不要对物品使用 Fortnite 物品商店术语，也不要使用 “XP” 等进度标记。玩家绝不能混淆：他们购买的物品是全 Fortnite 通用，还是仅限你的岛屿使用。

关于岛内变现的条款与命名指南的更多细节，请参阅条款与命名。

更多信息请参阅岛内交易限制(In-Island Transactions Restrictions)。

捆绑包商品(Bundle Offers)

捆绑包在 Verse 中定义，可包含不同商品的组合、同一商品的叠加，或两者混合。与简单商品一样，捆绑包商品有自己独立的价格、名称、描述，以及与权益和商品不同的图标。你还可以嵌套商品，即在捆绑包中包含捆绑包，例如限时捆绑包中同时包含一把铲子与一捆玉米种子包。这样你就能把小捆绑包当作积木，拼出更大的组合捆绑包。

标准捆绑包类型有：

  • 堆叠捆绑包(Stacked bundle)：包含同一权益多个商品的捆绑包，通常为折扣价。
  • 多商品捆绑包(Multi-offer bundle)：组合多个权益商品的捆绑包，也可混合堆叠商品与普通商品。

嵌套商品的深度不得超过 5，否则交易将失败。请尽量减少商品嵌套。

动态创建的商品

动态创建的商品是指在 Verse 运行时生成的商品或捆绑包商品。动态商品的常见用例包括：

  • 为采集建造类游戏出售玩家可持有的最大数量木材。
  • 为地牢爬行类游戏在地牢入口出售回满生命与魔法药水的捆绑包。

为简单起见，可将其绑定到按钮或告示牌等简单对象上。在 Verse 代码中流程为：交互时(On Interaction) > 调用 BuyOffer。

以下代码片段展示了出售玩家可持有上限的玉米种子捆绑包的一种写法，购买失败时会打印错误信息。

TryBuyOffer(Player : player)<suspends>:void = Purchases := GetPurchasedEntitlements(Player, Entitlements.corn_seed_pack) var NumPlayerCornSeedPacks : int = 0 if (Purchase := Purchases[0]): set NumPlayerCornSeedPacks = Purchase(1) # Limit to at least 1 packet. # If the player has the maximum amount, the offer displays with a disabled purchase button. NumCornSeedPacks := Max(1, Entitlements.corn_seed_pack{}.MaxCount - NumPlayerCornSeedPacks)

商品验证规则

有效的商品或捆绑包商品必须遵循以下准则，不符合的购买将无法通过审核。定义有效商品的规则如下：

  • 嵌套商品深度不得超过5。
  • 每个商品的权益标识符总数不得超过每个商品 100 个，即一次出售的不同权益最多 100 种。
  • 商品价格必须在50至5000 V-Bucks 之间，且只能为50 的倍数。
  • 商品Name（名称）默认文本不得超过50个字符。
  • 商品Description（描述）默认文本不得超过500个字符。
  • 商品ShortDescription（短描述）默认文本不得超过100个字符。
  • 商品必须至少包含 1 项权益。
  • 商品所含某权益的数量不得超过该权益的MaxCount。
  • 商品不得包含MaxCount > 1 的耐久型权益。

你可以选择限制商品的展示位置与可见人群。更多信息请参阅岛内交易限制(In-Island Transactions Restrictions)。

创建店面

权益及其商品与捆绑包都已就绪，现在你需要一个出售它们的地方！

默认 UI

默认店面 UI 打开后会列出你添加的所有权益与商品，列表中第一项高亮，并在旁边的窗口中展示该权益的概览。

  • 店面可以有多页。
  • 超过五项的列表可滚动。

玩家通过调用BuyOffer方法，或使用带ShowOffersDialog方法的默认店面来触发购买流程。以下是可用于将店面购买流程融入游戏设计的部分设备示例：

  • 区域(Volumes)设备
  • 场景图计时器(Scene Graph Timer)设备
  • NPC
  • 对话(Conversation)设备

设计店面时的最佳实践是：由玩家主动选择打开购买流程。跳过这一步、强行向玩家弹出购买流程，会剥夺玩家自主权，容易引起不满。

所有商品都有购买(Purchase)与查看(Inspect)按钮，可打开市场窗口购买物品或查看商品内容。只有捆绑包才有查看捆绑包(Inspect Bundle)按钮。

选择关闭(Close)按钮可关闭市场。

商店体验完全由开发者掌控：

  • 由你决定向玩家提供哪些物品或玩法属性。
  • 由你为每个商品或捆绑包商品定价。
  • 你可以展示自己的店面，也可以使用 Fortnite 预制店面 UI。

其他功能

付费随机物品

在岛屿中提供付费随机物品有两种方式：

  • 直接以 V-Bucks 出售。
  • 允许玩家购买可用 V-Bucks 购买的权益，再兑换随机奖励或影响获得随机奖励的概率（间接提供）。

当创建直接授予随机奖励、或只能兑换随机奖励的物品时，必须将该权益的PaidRandomItem设为 true，并在购买前披露每种可能随机物品的准确数字概率。可直接在商品描述中披露准确数字概率，或在商品描述中说明概率查看位置。

示例如下：

  • 如果你以 V-Bucks 出售“神秘物品箱”，必须将该权益的PaidRandomItem设为true，并披露每种可能物品的准确数字概率。
  • 如果你以 V-Bucks 出售“幸运加成”，可提高玩家在玩法中获得随机物品的概率，必须将该权益的PaidRandomItem设为true，并披露每种可能物品的准确数字概率。
  • 如果你以 V-Bucks 出售只能兑换随机物品的“代币”，必须使用RestrictPaidRandomItems函数，防止无权限玩家获得随机奖励。
  • 如果你以 V-Bucks 出售可兑换多种物品（含随机物品）的“代币”，必须使用RestrictPaidRandomItems函数，防止无权限玩家获得随机奖励。

如果你提供可兑换多种物品（含随机奖励）的内容，必须使用RestrictPaidRandomItems函数，防止无权限玩家获得随机奖励，且必须在玩家获得随机奖励前披露每种可能物品的准确数字概率。

直接购买提示

对玩法有实质影响

如果你出售的物品能让玩家在岛屿中获得有意义的优势，必须将ConsequentialToGameplay设为true。

对玩法有实质影响的物品包括：购买后能为玩家带来有意义优势的一切情形，可能是直接的（如提升玩家游戏进度速度、强度或能力的物品），也可能是间接的（如授予可显著影响玩家通关速度或胜率的物品的访问权）。

如果你出售的物品另有免费替代品，所有玩家在商品展示的同时、无需任何条件即可获得同样优势，则无需将ConsequentialToGameplay设为true。这意味着玩家无需完成特定任务或满足玩法要求即可获得该物品。

如果物品对玩法仅有附带的、微不足道的影响，例如颜色不同但玩法相同、仅在不同环境中可见度略有差异，则无需将ConsequentialToGameplay设为 true。
