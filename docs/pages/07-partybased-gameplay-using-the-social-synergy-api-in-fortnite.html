社交协同 API 与小队玩法

用 Verse Social Synergy API 读取玩家小队（Party）成员，构建小队加成、专属区域、友伤减免与动态播报等社交玩法。

英文原标题：Party-Based Gameplay Using the Social Synergy API in Fortnite · 查看英文原文 · 社区翻译镜像，仅供学习

Verse Social Synergy API（社交协同 API）会上报玩家的小队（Party）成员关系，让你能够基于“玩家带了谁一起来”构建响应式玩法。小队（Party）是指玩家在 Epic 生态（Fortnite、Epic Games 启动器与 Epic 移动应用）中组建的同行分组；它不是队伍（Team），也不是由匹配（matchmaking）生成的分组。

本指南概述该 API 中的类与函数，并给出构建社交机制的示例代码片段，包括：

  • 小队计分加成（Score bonuses for parties）
  • 仅限小队进入的区域（Party-only access to an area）
  • 随小队规模缩放的难度（Difficulty that scales to party size）
  • 小队成员之间的友伤减免（Reduced friendly fire between party members）
  • 动态解说与 UI（Dynamic commentary and UI）
  • 基于小队的装饰性视觉特效（Party-based cosmetic visual effects，VFX）

开始之前

为更好地理解本页内容：

  • 先查阅 Social 模块参考（Social module reference）。
  • 对 Verse 有基本了解。学习请见 Verse 编程入门指南。
  • 本页每个示例都使用一个 Verse 设备（Verse device）。创建方法请见 在 UEFN 中使用 Verse 创建你自己的设备。

基于小队的玩法受 Fortnite 开发者规则（Fortnite Developer Rules）约束，发布前请先查阅相关规则。

Social Synergy API 的工作原理

该 API 包含定义在玩家（player）上的函数 GetLocalParty()。它返回一个持有小队成员与小队事件的分组对象（group object）。也就是说，你是在某个玩家身上调用它，而不是把玩家传给它。

该分组是单个值（single value），不是列表，也不是计数。

# 扩展函数是在玩家身上调用，而不是把玩家传进去
Party := SomePlayer.GetLocalParty()

要使用该 API，请在 using 块中引入 Social 与 Agent Group 模块：

using { /UnrealEngine.com/Social }
using { /Verse.org/AgentGroup }
using { /Verse.org/Simulation }

该分组只包含当前会话（session）中在场的小队成员。玩家的小队可能超出你的岛屿范围，不在岛上的成员不在该分组内。玩家始终处于至少有一名成员的小队中，因此该分组始终至少包含一名成员；小队规模为 1 即表示单排玩家（solo player）。

该分组支持以下操作：

  • 读取成员。GetMemberMap() 返回成员表，既能得到小队规模，也能逐个成员执行逻辑。
  • 在分组变化时响应。该分组会发出事件信号（signals events），订阅后，每当有成员加入或离开，你的代码就会运行。
  • 比较玩家的从属关系。同一小队中的两名玩家会拿到相同的分组对象，因此比较两次调用结果即可判断两名玩家是否在同一小队。

完整签名与说明符请见 Social 模块参考中的 GetLocalParty 页面。

读取玩家小队以控制区域准入

GetMemberMap() 返回一张映射表，将每名小队成员的 agent 与其 party_member_info 配对。party_member_info 目前不携带字段，因此你要读取的是成员本身：读 Length 得到小队规模，或遍历该表逐个成员执行逻辑。

下面的示例读取小队规模来控制一道屏障（Barrier）：当玩家与按钮交互时，Verse 设备检查该玩家是否有小队成员在场，并把该玩家加入 Barrier 设备的忽略列表，从而为其放行。

搭建小队屏障的步骤：

  • 在岛屿上放置一个 HUD 消息（HUD Message）设备、一个 屏障（Barrier）设备和一个 按钮（Button）设备。把按钮放在屏障旁边，并保持屏障启用，使该区域初始为锁定状态。
  • 创建一个名为 party_area_device 的 Verse 设备，为上述三个设备分别添加可编辑属性（editable properties）。
using { /Fortnite.com/Devices }
using { /Fortnite.com/FortPlayerUtilities }
using { /UnrealEngine.com/Social }
using { /Verse.org/AgentGroup }
using { /Verse.org/Simulation }

# 挡住该区域的屏障设备，在 Details 面板中指派
party_area_device := class(creative_device):
    @editable
    Barrier : barrier_device = barrier_device{}
    @editable
    BarrierButton : button_device = button_device{}
    @editable
    DenialHUD : hud_message_device = hud_message_device{}
  • 为拒绝提示文案及其显示时长添加可编辑属性，并一并添加 StringToMessage 辅助函数，因为 HUD 设备接收的是 message 而非 string，而该辅助函数不在标准库中。
# 区域锁定时显示的提示文案
    @editable
    NoPartyMessage : string = "You need a party member on the island to unlock this area."
    # 拒绝消息在屏幕上的停留时长（秒）
    @editable
    MessageDisplayTime : float = 3.0
    # 把运行时字符串转为 HUD 设备所需的本地化消息类型，
    # 声明在类内部，供本设备上的所有逻辑使用
    StringToMessage(S : string) : message = "{S}"

同一文件夹下的每个 Verse 文件属于同一模块、共享同一命名空间，因此你可以在某个 Verse 文件的文件作用域声明一次 StringToMessage；也可以在共享文件中添加 module 块，并在需要时导入该模块。详见《Verse 之书（Book of Verse）》中的 Modules and Paths。

  • 在 OnBegin() 中订阅按钮的交互事件。OnBegin() 每个设备只运行一次，因此只会注册一次处理函数。
OnBegin<override>()<suspends>:void =
        # 在会重复运行的位置订阅会产生重复处理函数，
        # 之后区域逻辑会按重复次数反复执行
        BarrierButton.InteractedWithEvent.Subscribe(OnBarrierButtonPressed)
  • 添加处理函数。InteractedWithEvent 传入的是 agent，而 GetLocalParty() 定义在 player 上，因此处理函数先做类型转换再读取小队。
OnBarrierButtonPressed(InAgent : agent) : void =
        # 已离开会话的玩家转换失败，if 直接跳过正文
        if (Player := player[InAgent]):
            # 长度判断用大于等于 2，而不是 > 0：
            # 独自一人的玩家本身就是规模为 1 的小队，> 0 会对所有人放行
            if (Player.GetLocalParty().GetMemberMap().Length >= 2):
                # 禁用屏障即放行。屏障设备启用时阻挡，
                # 因此这里调用的是 Disable() 而不是 Enable()
                Barrier.Disable()
                # TODO: 把 Player 加入忽略列表 / 记录已放行
            else:
                # 显示拒绝提示
                DenialHUD.Show(Player, StringToMessage(NoPartyMessage))
  • 编译 Verse 代码，把 Verse 设备拖入岛屿，在 Details 面板中把 Barrier、Button 与 HUD Message 设备指派到对应的可编辑属性。
  • 用同属一个小队的两个账号测试，确认区域放行；再用单个账号测试，确认改为显示提示消息。

请为单人玩家保留一条绕过屏障的路线，例如第二个入口、延时自动解锁的计时器，或等价资源。没有单人通路的小队门禁可能让岛屿的一部分对部分玩家完全不可达。

小队成员加入或离开时响应

该分组会发出以下事件，每个事件都传递一个持有变化成员及其信息的 tuple(agent, party_member_info)：

  • AddMemberEvent：当小队成员加入分组时触发。
  • RemoveMemberEvent：当小队成员离开分组时触发。
  • MemberInfoChangeEvent：当某成员的 party_member_info 被重新实例化时触发。由于 party_member_info 为空，请订阅 AddMemberEvent 与 RemoveMemberEvent 即可。

下面的示例订阅 AddMemberEvent 与 RemoveMemberEvent，并向受影响的玩家显示抬头显示（HUD）消息。

搭建通知设备的步骤：

  • 在岛屿上放置一个 HUD 消息设备。
  • 创建一个名为 party_notification_device 的 Verse 设备，并在设备类上方添加一个 party_listener 类，用于持有要通知的玩家以及每条通知所需的值。
using { /Fortnite.com/Devices }
using { /Fortnite.com/Characters }
using { /Fortnite.com/Game }
using { /UnrealEngine.com/Social }
using { /Verse.org/AgentGroup }
using { /Verse.org/Simulation }

party_listener := class:
    TargetPlayer : player
    HUD : hud_message_device
    JoinText : string
    LeftText : string
    ShowTime : float

该监听器是通用模式，而非通知专用。每当回调需要知道自己在为哪名玩家工作，一个持有玩家并自行订阅的小类就能提供该上下文，因为 Verse 没有闭包（closures）可在订阅点捕获它。party_listener 是普通类而非设备，因此不会出现在 Details 面板，也不需要在关卡中放置。

  • 为监听器添加 StartListening()。监听器订阅自身，因此两个回调都是对其自身方法的引用。
StartListening() : void =
        # 一次调用、两次订阅：两个事件位于同一分组对象上
        Party := TargetPlayer.GetLocalParty()
        Party.AddMemberEvent.Subscribe(OnMemberAdded)
        Party.RemoveMemberEvent.Subscribe(OnMemberRemoved)
  • 添加两个处理函数，每个函数接收一个持有变化成员的元组。
OnMemberAdded(MemberInfo : tuple(agent, party_member_info)) : void =
        # 元素 0 是发生变化的 agent，
        # 元素 1 是其 party_member_info（为空）
        JoinedAgent := MemberInfo(0)
        HUD.Show(TargetPlayer, StringToMessage(JoinText))

    # 与 OnMemberAdded 对称，元素 0 是离开的 agent
    OnMemberRemoved(MemberInfo : tuple(agent, party_member_info)) : void =
        LeftAgent := MemberInfo(0)
        HUD.Show(TargetPlayer, StringToMessage(LeftText))
  • 添加设备类，为 HUD 消息设备与两条消息字符串添加可编辑属性。
party_notification_device := class(creative_device):
    # 显示通知的 HUD 消息设备，在 Details 面板中指派
    @editable
    NotificationDevice : hud_message_device = hud_message_device{}
    # 有小队成员加入会话时显示的消息
    @editable
    JoinedMessage : string = "A party member joined the island!"
    # 有小队成员离开会话时显示的消息
    @editable
    LeftMessage : string = "A party member left the island!"
    @editable
    MessageDisplayTime : float = 3.0
  • 在 OnBegin() 中先覆盖会话中已有的每名玩家，再订阅 PlayerAddedEvent()。已在场的玩家与稍后加入的玩家是两种情形，要分别处理。
OnBegin<override>()<suspends>:void =
        # 覆盖设备启动时已在场的所有人
        for (Player : GetPlayspace().GetPlayers()):
            SubscribeToPartyEvents(Player)
        # 覆盖会话开始后加入的所有人
        GetPlayspace().PlayerAddedEvent().Subscribe(OnPlayerJoined)

    OnPlayerJoined(InPlayer : player) : void =
        SubscribeToPartyEvents(InPlayer)
  • 添加 SubscribeToPartyEvents()，为每名玩家各构建一个监听器并启动。只在初始化时调用它，因为在事件处理函数内订阅会使该事件每次触发都叠加一次订阅。
SubscribeToPartyEvents(InPlayer : player) : void =
        # 同一小队的两名玩家共享同一个分组对象，
        # 因此两次订阅落在同一个对象上。各自携带自己的监听器触发，
        # 每名玩家各收到一条消息
        Listener := party_listener:
            TargetPlayer := InPlayer
            HUD := NotificationDevice
            JoinText := JoinedMessage
            LeftText := LeftMessage
            ShowTime := MessageDisplayTime
        Listener.StartListening()
  • 编译 Verse 代码，把设备放入岛屿，在 Details 面板把 HUD 消息设备指派到 NotificationDevice 选项。
  • 用同属一个小队的两个账号测试：让第二个账号加入再离开会话，确认每次变化各出现一条消息。

HUD 消息不只是宣告变化，还可以告诉玩家现在解锁了什么。例如，早前被小队区域拒之门外的玩家，可以在条件满足时收到“现在可以打开了”的提示，省去折返确认；同一条消息也可以用来 gating 任务、载具，或任何需要第二名玩家在场的其他内容。

using { /Fortnite.com/Characters }
using { /Fortnite.com/Game }
using { /UnrealEngine.com/Social }
using { /Verse.org/AgentGroup }
using { /Verse.org/Simulation }
using { /UnrealEngine.com/Temporary/Diagnostics }

比较两名玩家以降低友伤

对同一小队中的两名玩家调用 GetLocalParty() 会返回同一个分组对象。因此用 = 比较两次结果，即可测试两名玩家是否在同一小队；比较的是对象标识（object identity），而不是成员列表。

下面的示例按双方关系缩放伤害：同一小队的成员相互伤害降低，其他人之间保持全额伤害。它只用一个 Verse 设备，返回一个倍率，再由你自己的伤害代码应用该倍率，例如带有自定义 Scene Graph（场景图）武器的项目。

该修正适用于玩家之间可以互相伤害的岛屿：自由混战（Free For All），或通过 岛屿设置（Island Settings）、队伍设置与备品（Team Settings and Inventory）设备启用 友伤（Friendly Fire） 的岛屿。

搭建伤害修正的步骤：

  • 创建一个名为 party_friendly_fire_device 的 Verse 设备，为两种情形分别添加可编辑倍率。小队倍率设为 0.0 即完全关闭小队成员之间的友伤。
using { /Fortnite.com/Devices }
using { /UnrealEngine.com/Social }
using { /Verse.org/AgentGroup }
using { /Verse.org/Simulation }

party_friendly_fire_device := class(creative_device):
    # 攻击者与目标在同一小队时应用，0.0 表示小队成员之间完全无友伤
    @editable
    DamageMultiplierForPartyMembers : float = 0.25
    @editable
    DamageMultiplierForNonParty : float = 1.0
  • 添加比较逻辑。这里测试对象标识，因此直接比较两个分组对象，忽略其成员列表。
# <public> 表示项目中的其他 Verse 设备也可以调用它
    CalculateDamageMultiplier<public>(Attacker : player, Target : player)<transacts>:float =
        # 同一小队的两名玩家拿到同一个分组对象，
        # 因此 = 成功；不同小队的两名玩家拿到不同对象，因此失败。
        # 比较忽略成员列表，可以安全地在每次伤害事件中运行
        if (Attacker.GetLocalParty() = Target.GetLocalParty()):
            DamageMultiplierForPartyMembers
        else:
            DamageMultiplierForNonParty
  • 编译 Verse 代码，把设备放入岛屿，在 Details 面板中设置两个倍率。
  • 在真正结算伤害的代码中调用 CalculateDamageMultiplier()，并把基础伤害乘以返回值。某些伤害路径会把玩家与自身比较；玩家始终处于至少规模为 1 的小队，因此单人玩家的分组与自身比较相等。
  • 把函数接入伤害代码后测试：用同属一个小队的两个账号确认相互伤害降低，再用分属不同小队的两个账号确认保持全额倍率。

如果还没有自己的伤害系统，也可以通过响应伤害达到类似效果：订阅角色的 DamagedEvent，它会发送持有 Target、Instigator 与 Amount 的 damage_result；比较两名玩家的从属关系，若目标与煽动者在同一小队，再把目标治疗回来。

把小队成员分到同一队伍

本示例用标识比较让小队保持在一起：当玩家加入时，设备寻找同一小队中的另一名玩家，并把新到达者移到该玩家所在的队伍。

该片段假设岛屿已配置固定队伍：在 岛屿设置（Island Settings）中把 队伍（Teams）设为具体数字而非 自由混战（Free For All），并提供至少与预期小队数量相当的队伍数。

自行拓展

可以这样延伸上述技巧：

  • 按小队规模缩放奖励。用源自 GetMemberMap().Length 的系数乘以分数或经验奖励，并设置上限，避免大队伍远超小队伍或单人玩家。
  • 第二名成员到达时显示提示。在密室逃脱中，当第二名小队成员中途加入谜题时激活提示系统，让所有玩家看到同一条提示。
  • 让合作 Boss 战保持可赢。用 RemoveMemberEvent 在小队成员掉线时降低 Boss 血量，使剩余玩家仍能打赢按更大规模调校的战斗。
  • 把迟到者送到小队身边。用 AddMemberEvent 把中途加入会话的玩家送到已在岛上的小队成员出生点。
  • 按小队分组结算界面。在结算界面按每名玩家的小队分组展示，而非纯按分数排序，方便好友之间比较成绩。
  • 塑造视觉标识。运行小队检查，为小队成员应用装饰性 VFX，增强沉浸感。
